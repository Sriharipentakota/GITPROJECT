BEGINNER1. What are Conditionals?

Conditionals let a program make decisions — running different code depending on whether something is true or false. Without them, every program would run the exact same sequence of steps every single time.

Real-world analogy: A conditional is like a traffic light. At each intersection, the light checks a condition and decides which cars go. if is the green light, else if is a secondary check, else is the fallback detour.

The Building Blocks

  • if — run code only when a condition is true
  • else — run alternative code when it's false
  • else if — check another condition if the first failed
  • switch — compare one value against many fixed options
  • ternary (?:) — an expression form of if/else
const isRaining = true;

if (isRaining) {
    console.log("Bring an umbrella");
} else {
    console.log("Enjoy the sun");
}

BEGINNER2. if / else if / else

JavaScript evaluates the condition inside if (...) and coerces it to a boolean. The braces {} — not indentation — define exactly what code belongs to each branch.

let score = 85;
let grade;

if (score >= 90) {
    grade = "A";
} else if (score >= 80) {
    grade = "B";       // ← this branch runs
} else if (score >= 70) {
    grade = "C";
} else {
    grade = "F";
}

console.log(grade); // "B"
⚠️ Mutual Exclusivity: In an if / else if / else chain, AT MOST ONE branch runs — JavaScript checks top to bottom and stops at the first truthy condition. Two SEPARATE if statements are NOT mutually exclusive — both can run if both conditions are true. 
// else if chain — mutually exclusive, only one runs
if (score >= 90) grade = "A";
else if (score >= 60) grade = "Pass"; // this catches score=95 too, but never runs
                                       // because the first branch already matched

// Two separate ifs — NOT mutually exclusive, BOTH can run
if (score >= 90) console.log("Excellent!");
if (score >= 60) console.log("You passed!"); // this ALSO runs for score=95

Braces Matter

// Without braces, only the NEXT line belongs to the if
if (isReady)
    console.log("A");
    console.log("B"); // ⚠️ this ALWAYS runs — it's not part of the if!

// Always use braces to avoid this trap
if (isReady) {
    console.log("A");
    console.log("B"); // now correctly scoped
}

BEGINNER3. Truthy and Falsy in Conditions

A condition doesn't have to be a literal true/false — ANY value can be used, and JavaScript coerces it. There are exactly 6 falsy values; everything else is truthy.

if ("")        console.log("A"); // skipped — empty string is falsy
if (0)         console.log("B"); // skipped — 0 is falsy
if (null)      console.log("C"); // skipped
if (undefined) console.log("D"); // skipped
if (NaN)       console.log("E"); // skipped
if (false)     console.log("F"); // skipped

if ([])        console.log("G"); // ✅ runs — empty array is truthy!
if ({})        console.log("H"); // ✅ runs — empty object is truthy!
if ("0")       console.log("I"); // ✅ runs — non-empty string, even "0", is truthy!
if (" ")       console.log("J"); // ✅ runs — a space is a non-empty string

Guard Pattern

function loadUser(user) {
    if (!user) {
        console.log("No user provided");
        return;
    }
    console.log(user.name);
}

// Common shorthand for "does this exist and is it truthy?"
if (isAuthenticated) {
    loadDashboard();
}

BEGINNER4. The switch Statement

switch is a cleaner alternative to a long if/else if chain when you're comparing ONE value against MANY fixed options. Internally it uses strict (===) comparison.

const day = 3;
let dayName;

switch (day) {
    case 1:
        dayName = "Monday";
        break;
    case 2:
        dayName = "Tuesday";
        break;
    case 3:
        dayName = "Wednesday";
        break;
    default:
        dayName = "Unknown";
}

console.log(dayName); // "Wednesday"
if/else chain (verbose): 
if (day === 1) {
    dayName = "Monday";
} else if (day === 2) {
    dayName = "Tuesday";
} else if (day === 3) {
    dayName = "Wednesday";
} else {
    dayName = "Unknown";
}
switch (cleaner for many fixed values): 
switch (day) {
    case 1: dayName = "Monday"; break;
    case 2: dayName = "Tuesday"; break;
    case 3: dayName = "Wednesday"; break;
    default: dayName = "Unknown";
}

INTERMEDIATE5. Fall-Through in switch

Without a break, execution falls through to the next case automatically — this can be a bug, or a deliberate technique for grouping cases that share behavior.

let day = 6;

switch (day) {
    case 6:
    case 7:
        console.log("Weekend"); // both 6 and 7 land here — intentional grouping
        break;
    default:
        console.log("Weekday");
}
// Output: "Weekend"
⚠️ Accidental Fall-Through: Forgetting break is one of the most common switch bugs. Without it, execution continues into the NEXT case's code even if that case's condition doesn't match. 
// BUG: missing break
switch (2) {
    case 1:
        console.log("one");
    case 2:
        console.log("two");    // runs
    case 3:
        console.log("three");  // ALSO runs — fell through, no break after "two"!
        break;
    default:
        console.log("other");
}
// Output: "two" then "three" — probably not intended!

return Instead of break

Inside a function, return also exits a switch — no break needed after it, since the whole function ends.

function getDayType(day) {
    switch (day) {
        case 6:
        case 7:
            return "Weekend";
        default:
            return "Weekday";
    }
}
console.log(getDayType(6)); // "Weekend"

INTERMEDIATE6. Ternary as a Conditional Expression

The ternary operator condition ? ifTrue : ifFalse is not a full statement replacement for if/else — it's an expression that produces a value, ideal for simple assignments.

const age = 20;
const status = age >= 18 ? "adult" : "minor";
console.log(status); // "adult"

// Useful inline in JSX/template strings too
const message = `You are ${age >= 18 ? "an adult" : "a minor"}.`;
💡 Tip: Use a ternary when you're producing a VALUE from a condition. Use if/else when you're running different BLOCKS of side-effecting code (multiple statements, no clean single value).

INTERMEDIATE7. Guard Clauses & Early Returns

A guard clause checks for an invalid/edge case up front and returns immediately, avoiding deeply nested if blocks.

❌ Deeply nested: 
function process(user) {
    if (user) {
        if (user.isActive) {
            if (user.hasPermission) {
                return doWork(user);
            } else {
                return "No permission";
            }
        } else {
            return "Inactive";
        }
    } else {
        return "No user";
    }
}
✅ Guard clauses (flat): 
function process(user) {
    if (!user) return "No user";
    if (!user.isActive) return "Inactive";
    if (!user.hasPermission) return "No permission";

    return doWork(user);
}

ADVANCED8. Combining Conditions

Real-world conditions often combine multiple checks with &&, ||, and !. Parentheses control grouping and readability.

const age = 25;
const hasLicense = true;
const hasInsurance = false;

if (age >= 18 && hasLicense && hasInsurance) {
    console.log("Can drive");
} else {
    console.log("Cannot drive"); // runs — hasInsurance is false
}

// Grouping matters
if ((role === "admin" || role === "moderator") && isActive) {
    console.log("Has elevated access");
}

Object Lookup Instead of Long else-if Chains

// Instead of a long if/else if chain for a fixed mapping...
function getColorForStatus(status) {
    const colors = {
        active: "green",
        pending: "yellow",
        inactive: "gray",
    };
    return colors[status] ?? "black"; // fallback for unknown status
}
console.log(getColorForStatus("pending")); // "yellow"

ADVANCED9. Common Pitfalls

1. Using = Instead of === (Accidental Assignment)

let x = 5;
// if (x = 10) { }   // ⚠️ assigns 10 to x, then evaluates 10 as truthy — BUG!
if (x === 10) { }    // ✅ correct comparison

2. Comparing Objects/Arrays Directly

if ([1,2] === [1,2]) { }   // always false — different array instances
if ({} === {}) { }         // always false — different object instances
// Compare contents instead, e.g. via JSON.stringify or a deep-equal helper

3. Forgetting break in switch

switch (status) {
    case "active":
        console.log("Active");
        // missing break — falls into "pending" case too!
    case "pending":
        console.log("Pending");
        break;
}

4. Truthy Object/Array Traps

const errors = [];
if (errors) {
    console.log("has errors"); // ⚠️ runs even though errors is EMPTY — [] is truthy!
}
// Correct: check length
if (errors.length > 0) {
    console.log("has errors"); // only runs when there really are errors
}

INTERMEDIATE10. Best Practices

1. Always Use Braces, Even for One-Liners

// ✅ Safe
if (isValid) {
    process();
}

// ❌ Risky if someone adds a line later without noticing scope
if (isValid) process();

2. Prefer Guard Clauses Over Deep Nesting

function getDiscount(user) {
    if (!user.isMember) return 0;
    if (user.yearsActive < 1) return 5;
    return 10;
}

3. Use switch for 3+ Fixed Value Comparisons

// ✅ Cleaner than 5 else-if branches
switch (httpStatus) {
    case 200: return "OK";
    case 404: return "Not Found";
    case 500: return "Server Error";
    default:  return "Unknown";
}

4. Check .length for Arrays, Not Truthiness

// ✅ Correct
if (items.length === 0) { showEmptyState(); }

// ❌ Wrong — arrays are always truthy, even empty ones
if (!items) { showEmptyState(); }

5. Use Explicit Comparisons for Clarity

// ✅ Clear
if (count === 0) { }

// Also fine, but be intentional about which you mean
if (!count) { } // true for 0, but ALSO true for NaN, undefined, etc.

📋 Quick Reference Summary

Concept Key Points
if / else if / else Mutually exclusive chain — first truthy branch wins, rest are skipped.
switch Compares one value against many with ===. Needs break to avoid fall-through.
Ternary Expression form of if/else — best for producing a single value.
Truthy/Falsy 6 falsy values: false, 0, "", null, undefined, NaN. [] and {} are truthy.
Guard clauses Return early for invalid cases to keep code flat and readable.
