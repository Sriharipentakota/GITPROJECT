BEGINNER1. What is a Promise?

A Promise is an object representing the eventual result of an asynchronous operation — like a network request or a timer. It has exactly three states: pending, fulfilled, or rejected. Once it settles (fulfilled or rejected), it never changes state again.

Real-world analogy: A Promise is like a restaurant order ticket. You place your order and get a ticket — it's pending. While the kitchen works, you can do other things. When the food is ready, the kitchen delivers it (resolve) or a waiter apologizes it's unavailable (reject). 
// A Promise represents "a value that will exist later"
const promise = fetch("/api/data"); // pending immediately
console.log(promise); // Promise {  }

BEGINNER2. Creating a Promise

Use new Promise((resolve, reject) => { ... }). The function you pass in (the "executor") runs immediately and synchronously; call resolve(value) to fulfill it or reject(reason) to reject it.

const p1 = new Promise((resolve, reject) => {
    const success = true;
    if (success) {
        resolve(42);              // moves to "fulfilled" with value 42
    } else {
        reject(new Error("failed")); // moves to "rejected" with this error
    }
});

// Simulating a delayed async operation
function wait(ms) {
    return new Promise(resolve => {
        setTimeout(() => resolve(`waited ${ms}ms`), ms);
    });
}
wait(1000).then(msg => console.log(msg)); // "waited 1000ms" (after 1 second)
💡 Tip: You rarely construct promises with new Promise() yourself in everyday code — most of the time you're consuming promises already returned by APIs like fetch() or wrapping a callback-based API to "promisify" it.

BEGINNER3. Consuming Promises: then, catch, finally

const p = new Promise((resolve) => resolve(10));

p.then(value => {
    console.log(value); // 10
});

const failing = new Promise((_, reject) => reject(new Error("oops")));

failing.catch(err => {
    console.log(err.message); // "oops"
});

// .finally() runs regardless of success or failure — great for cleanup
p.finally(() => console.log("done")); // "done" — always runs

// .then() actually accepts TWO callbacks: onFulfilled and onRejected
p.then(
    value => console.log("success:", value),
    err   => console.log("failure:", err)
);

INTERMEDIATE4. Chaining Promises

Each .then() returns a NEW Promise, which lets you chain asynchronous steps in sequence, reading top-to-bottom instead of nesting callbacks.

fetch("/api/user/1")
    .then(response => response.json())     // parse JSON — returns a new promise
    .then(user => fetch(`/api/posts/${user.id}`)) // fetch related data
    .then(response => response.json())
    .then(posts => console.log(posts))
    .catch(err => console.log("Something failed:", err));

// Returning a PLAIN VALUE from .then() auto-wraps it in a resolved promise
Promise.resolve(10)
    .then(n => n * 2)        // returns 20, auto-wrapped
    .then(n => n + 5)        // receives 20, returns 25
    .then(n => console.log(n)); // 25
❌ Callback hell (pre-Promise style): 
getUser(1, function(user) {
    getPosts(user.id, function(posts) {
        getComments(posts[0].id, function(comments) {
            console.log(comments);
        });
    });
});
✅ Flat promise chain: 
getUser(1)
    .then(user => getPosts(user.id))
    .then(posts => getComments(posts[0].id))
    .then(comments => console.log(comments))
    .catch(err => console.log(err));

INTERMEDIATE5. Error Propagation in Chains

When a promise rejects (or a .then() callback throws), the error SKIPS every subsequent .then() and jumps straight to the nearest .catch() down the chain.

Promise.resolve()
    .then(() => {
        throw new Error("step 1 failed");
    })
    .then(() => {
        console.log("this NEVER runs"); // skipped entirely
    })
    .then(() => {
        console.log("this NEVER runs either"); // skipped too
    })
    .catch(err => {
        console.log("Caught:", err.message); // "Caught: step 1 failed"
    })
    .then(() => {
        console.log("chain continues normally after catch"); // this DOES run
    });
⚠️ Common Pitfall: A .catch() only catches errors from steps ABOVE it in the chain. If you add more .then() calls after the .catch(), errors in THOSE need their own .catch() — the chain "recovers" after a catch and continues as normal.

INTERMEDIATE6. Promise.all

Promise.all() runs multiple promises CONCURRENTLY and waits for all of them. If ANY of them rejects, the whole thing rejects immediately with that error — "all or nothing."

const p1 = Promise.resolve("first");
const p2 = new Promise(resolve => setTimeout(() => resolve("second"), 100));
const p3 = Promise.resolve("third");

Promise.all([p1, p2, p3]).then(results => {
    console.log(results); // ["first", "second", "third"] — same order as input, not completion order
});

// If ANY promise rejects, Promise.all rejects immediately
const willFail = Promise.reject(new Error("boom"));
Promise.all([p1, willFail, p3])
    .then(results => console.log(results))     // never runs
    .catch(err => console.log(err.message));    // "boom" — fails fast

ADVANCED7. Promise.allSettled, race, any

Method Resolves When Use Case
Promise.all()All fulfill (rejects if any reject)Need every result, all-or-nothing
Promise.allSettled()All settle (fulfilled OR rejected)Want every outcome, failures included
Promise.race()First one to settle (fulfill or reject)Timeout patterns, "fastest wins"
Promise.any()First one to FULFILL (ignores rejections)Try multiple sources, need just one success
const p1 = Promise.resolve("a");
const p2 = Promise.reject("b failed");
const p3 = Promise.resolve("c");

// allSettled — always resolves, gives status + value/reason for each
Promise.allSettled([p1, p2, p3]).then(results => {
    console.log(results);
    // [{status:"fulfilled", value:"a"}, {status:"rejected", reason:"b failed"}, {status:"fulfilled", value:"c"}]
});

// race — settles as soon as the FIRST promise settles (win OR lose)
Promise.race([p1, p2]).then(v => console.log(v)).catch(e => console.log(e));
// "a" — p1 resolves first (both are already-resolved, p1 was passed first)

// any — settles as soon as the first promise FULFILLS, ignoring rejections
Promise.any([p2, p1, p3]).then(v => console.log(v)); // "a" — first fulfillment, p2's rejection is ignored

Timeout Pattern with race

function withTimeout(promise, ms) {
    const timeout = new Promise((_, reject) =>
        setTimeout(() => reject(new Error("Timed out")), ms)
    );
    return Promise.race([promise, timeout]);
}
// Whichever settles first wins — the real request, or the timeout

ADVANCED8. The Microtask Queue

Promise callbacks (.then, .catch, .finally) run in the microtask queue, which is processed AFTER all synchronous code finishes, but BEFORE the browser moves on to macrotasks like setTimeout.

console.log("1: sync start");

setTimeout(() => console.log("2: setTimeout (macrotask)"), 0);

Promise.resolve().then(() => console.log("3: promise .then (microtask)"));

console.log("4: sync end");

// Actual output order:
// "1: sync start"
// "4: sync end"
// "3: promise .then (microtask)"   ← runs before setTimeout, even with 0ms delay!
// "2: setTimeout (macrotask)"
💡 Tip: This is why a Promise.resolve().then(...) ALWAYS runs before a setTimeout(..., 0), no matter how the code is arranged — the microtask queue is always fully drained before the next macrotask runs.

ADVANCED9. Common Pitfalls

1. Forgetting to Return Inside a .then()

// ❌ Missing return breaks the chain — next .then() gets undefined immediately
fetchUser(1)
    .then(user => {
        fetchPosts(user.id); // forgot "return" here!
    })
    .then(posts => {
        console.log(posts); // undefined — didn't actually wait for fetchPosts
    });

// ✅ Correct
fetchUser(1)
    .then(user => {
        return fetchPosts(user.id); // properly chains
    })
    .then(posts => console.log(posts));

2. Not Handling Rejections (Unhandled Promise Rejection)

// ❌ No .catch() — if this rejects, it becomes an "unhandled promise rejection"
fetchData().then(data => console.log(data));

// ✅ Always handle failure paths
fetchData()
    .then(data => console.log(data))
    .catch(err => console.error("Failed:", err));

3. Nesting Promises Instead of Chaining

// ❌ Defeats the purpose of promises — back to callback-style nesting
fetchUser(1).then(user => {
    fetchPosts(user.id).then(posts => {
        console.log(posts);
    });
});

// ✅ Flatten with proper chaining
fetchUser(1)
    .then(user => fetchPosts(user.id))
    .then(posts => console.log(posts));

4. Promise.all Failing Fast Hides Other Results

// If you need ALL outcomes even when some fail, use allSettled instead of all
Promise.all([fetchA(), fetchB()]) // if fetchB rejects, you never see fetchA's result
    .catch(err => console.log("Lost visibility into which one succeeded"));

INTERMEDIATE10. Best Practices

1. Always Add a .catch() (or try/catch with async/await)

// ✅ Every promise chain should handle failure
doSomethingAsync()
    .then(handleSuccess)
    .catch(handleError);

2. Return Promises From .then() to Keep Chains Flat

// ✅ Flat, readable
step1().then(result => step2(result)).then(result => step3(result));

3. Use Promise.all for Independent Parallel Work

// ✅ Faster — runs concurrently instead of one after another
const [user, settings] = await Promise.all([fetchUser(), fetchSettings()]);

4. Use allSettled When Partial Failure Is Acceptable

// ✅ Get every outcome, don't lose successful results to one failure
const results = await Promise.allSettled([fetchA(), fetchB(), fetchC()]);
const succeeded = results.filter(r => r.status === "fulfilled").map(r => r.value);

5. Prefer async/await for Complex Chains (See the Async/Await Guide)

// ✅ Often more readable than long .then() chains
async function loadData() {
    const user = await fetchUser();
    const posts = await fetchPosts(user.id);
    return posts;
}

📋 Quick Reference Summary

Concept Key Points
States Pending → Fulfilled or Rejected. Settles exactly once, permanently.
then/catch/finally Consume results, handle errors, always-run cleanup respectively.
Chaining Each .then() returns a new promise — return values/promises to keep chaining.
Error propagation Rejections skip .then() handlers until the next .catch().
Promise.all All-or-nothing — fails fast if any promise rejects.
allSettled/race/any allSettled = every outcome; race = first to settle; any = first to succeed.
Microtasks Promise callbacks run before setTimeout, after synchronous code.
