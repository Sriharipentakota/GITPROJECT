BEGINNER1. What is a Data Type?

Every value in JavaScript belongs to a data type — a category that determines what the value looks like and what operations are valid on it. JavaScript has 8 built-in types, split into two families: primitives (7 of them) and objects (everything else).

Real-world analogy: Think of types as different container shapes. A number is a measuring cup, a string is an envelope, a boolean is a light switch. You can't pour liquid into an envelope — likewise, JavaScript restricts what operations make sense for each type.

Why Types Matter

  • Correctness: Knowing a value's type prevents subtle bugs (like adding a string to a number)
  • Memory & performance: Primitives and objects are stored differently
  • API design: Function behavior often depends on the type of what's passed in

Dynamic Typing

JavaScript is dynamically typed — a variable's type isn't declared up front, it's determined by whatever value currently sits in it, and it can change over time.

let value = 42;          // value is currently a number
console.log(typeof value); // "number"

value = "hello";         // now it's a string
console.log(typeof value); // "string"

value = true;            // now it's a boolean
console.log(typeof value); // "boolean"
💡 Tip: This is different from statically typed languages (like Java or C#) where a variable is locked to one type forever. Dynamic typing gives flexibility but also means you need to be careful about what a variable currently holds.

BEGINNER2. The Primitive Types

Primitives are immutable (a primitive value itself can never be changed, only replaced) and are compared/copied by value. JavaScript has exactly 7 primitive types.

1. string

const single = 'Hello';
const double = "World";
const template = `Hello, ${double}!`;   // template literal — supports interpolation

console.log(template);         // "Hello, World!"
console.log(typeof template);  // "string"

2. number

JavaScript has only ONE numeric type for regular numbers — no separate int/float/double like other languages. It's a 64-bit floating point (IEEE 754) value.

const integer = 42;
const float = 3.14;
const negative = -17;
const scientific = 2.5e6;     // 2,500,000
const infinity = Infinity;
const notANumber = NaN;

console.log(typeof integer);  // "number"

3. boolean

const isLoggedIn = true;
const hasError = false;

console.log(typeof isLoggedIn); // "boolean"

4. undefined

Represents a variable that has been declared but not yet assigned a value. It's also what a function returns by default, and what you get accessing a missing object property.

let x;
console.log(x);          // undefined
console.log(typeof x);   // "undefined"

function noReturn() {}
console.log(noReturn()); // undefined

const obj = {};
console.log(obj.missingProp); // undefined

5. null

null represents an intentional absence of value — you assign it deliberately to say "this should have no value."

let selectedUser = null; // explicitly "nothing selected yet"
console.log(selectedUser);      // null
console.log(typeof selectedUser); // "object" — see Section 4 for why!

6. bigint

For integers larger than Number.MAX_SAFE_INTEGER (2^53 - 1). Append n to a numeric literal, or use the BigInt() function.

const huge = 9007199254740993n;
const fromFn = BigInt("123456789012345678901234567890");

console.log(typeof huge);      // "bigint"
console.log(huge + 1n);        // 9007199254740994n — must mix with other BigInts, not numbers

// console.log(huge + 1);      // ❌ TypeError: Cannot mix BigInt and other types

7. symbol

A Symbol is a guaranteed-unique value, typically used as a "hidden" object property key to avoid naming collisions.

const id1 = Symbol("id");
const id2 = Symbol("id");

console.log(id1 === id2);   // false — every symbol is unique, even with the same description
console.log(typeof id1);    // "symbol"

const user = { name: "Alice", [id1]: "internal-id-123" };
console.log(user[id1]);     // "internal-id-123"
Type Example typeof result Mutable?
string "hi" "string" ❌ No
number 42 "number" ❌ No
boolean true "boolean" ❌ No
undefined undefined "undefined" ❌ No
null null "object" (quirk) ❌ No
bigint 10n "bigint" ❌ No
symbol Symbol() "symbol" ❌ No

BEGINNER3. Reference Types (Objects)

Everything that is not a primitive is an object — this includes plain objects, arrays, functions, dates, maps, sets, and regular expressions. Objects are mutable and are stored/compared by reference.

Object Literal

const person = { name: "Bob", age: 30 };
console.log(typeof person); // "object"

Array

const numbers = [1, 2, 3];
console.log(typeof numbers);        // "object" — yes, really!
console.log(Array.isArray(numbers)); // true — use this to detect arrays

Function

function greet() { return "hi"; }
console.log(typeof greet); // "function" — the ONE exception that gets its own typeof result

Date, Map, Set, RegExp

const now = new Date();
const map = new Map();
const set = new Set([1, 2, 3]);
const pattern = /[a-z]+/;

console.log(typeof now, typeof map, typeof set, typeof pattern);
// "object" "object" "object" "object" — all are reference types
Key distinction: Primitives hold their value directly. Objects hold a reference (a memory address) — the variable doesn't contain the object itself, it contains a pointer to where the object lives.

INTERMEDIATE4. typeof and Its Quirks

The typeof operator returns a string describing a value's type. It's extremely useful, but has a few well-known historical quirks you must memorize.

typeof "hello"      // "string"
typeof 42            // "number"
typeof true           // "boolean"
typeof undefined      // "undefined"
typeof Symbol()       // "symbol"
typeof 10n            // "bigint"
typeof {}             // "object"
typeof []             // "object"   ← arrays are objects
typeof function(){}   // "function" ← special-cased, not "object"
typeof null           // "object"   ← famous bug!
⚠️ The null Bug: typeof null === "object" is a bug from JavaScript's very first version (1995) that was never fixed because doing so would break too much existing code on the web. null is NOT actually an object — treat it as its own special "intentional empty" primitive. To check for null specifically, use value === null.

Reliable Type-Checking Recipes

// Arrays
Array.isArray([1, 2, 3]);          // true

// null
value === null;                    // true only for null

// NaN
Number.isNaN(NaN);                 // true — safe, unlike global isNaN()

// Plain object (not array, not null)
typeof value === "object" && value !== null && !Array.isArray(value);

// Any "is nothing" check
value == null;   // true for BOTH null and undefined (the one good use of ==)

INTERMEDIATE5. Type Coercion (Implicit vs Explicit)

JavaScript will often convert values between types automatically. This is implicit coercion. You can also convert values yourself on purpose — explicit coercion — which is almost always the safer, more readable choice.

Implicit Coercion

"5" + 3        // "53"   — + treats it as string concatenation because one side is a string
"5" - 3        // 2      — minus forces both sides to numbers
"5" * "2"      // 10     — * also forces numbers
true + 1       // 2      — true becomes 1
false + 1      // 1      — false becomes 0
"5" == 5       // true   — loose equality coerces types before comparing
[] + []        // ""     — both arrays convert to strings, then concatenate
[] + {}        // "[object Object]" — quirky but explainable once you know the rules

Explicit Coercion

Number("42");        // 42
Number("42px");      // NaN — must be a clean numeric string
String(99);          // "99"
String(null);        // "null"
Boolean(1);           // true
Boolean(0);           // false
parseInt("42px", 10); // 42 — parses as much as it can, unlike Number()
parseFloat("3.14m");  // 3.14
❌ Relying on implicit coercion: 
function addToCart(qty) {
    return qty * 2; // if qty is "3" (string from
                     // a form input), this "works"
                     // by accident: "3" * 2 = 6
}
✅ Explicit and predictable: 
function addToCart(qty) {
    const n = Number(qty);
    if (Number.isNaN(n)) {
        throw new Error("Invalid quantity");
    }
    return n * 2;
}

BEGINNER6. Truthy and Falsy Values

When a value is used where a boolean is expected (an if condition, &&, ||, ternary), JavaScript coerces it to true or false. There are exactly 6 falsy values — everything else is truthy.

Falsy Value Notes
falseThe boolean itself
0 (and -0)Numeric zero
""Empty string
nullIntentional absence
undefinedUnassigned
NaNNot-a-Number
⚠️ Common Pitfall: [] (empty array) and {} (empty object) are BOTH truthy! Beginners often expect them to be falsy because they "look empty," but any object — even an empty one — is truthy. 
if ([])  console.log("runs");   // ✅ runs — [] is truthy
if ({})  console.log("runs");   // ✅ runs — {} is truthy
if (0)   console.log("skipped"); // ❌ skipped — 0 is falsy
if ("0") console.log("runs");   // ✅ runs — non-empty string is truthy, even "0"!

ADVANCED7. Value vs Reference Comparison

Primitives are compared by their actual value. Objects are compared by identity — whether they are literally the same object in memory, not whether their contents look the same.

// Primitives — compared by value
console.log(5 === 5);           // true
console.log("hi" === "hi");     // true

// Objects — compared by reference
console.log({ a: 1 } === { a: 1 }); // false — two different objects, same shape
console.log([1,2] === [1,2]);       // false — two different arrays

const obj1 = { a: 1 };
const obj2 = obj1;               // obj2 points to the SAME object
console.log(obj1 === obj2);      // true — same reference
To compare object contents, you need a deep-equality check — either write one, use a library (like Lodash's isEqual), or for simple flat objects: JSON.stringify(a) === JSON.stringify(b) (imperfect — key order and special values like undefined/functions can trip it up).

ADVANCED8. NaN and Numeric Edge Cases

NaN ("Not a Number") is the result of an invalid numeric operation. It has one very strange property: it is the ONLY value in JavaScript that is not equal to itself.

console.log(NaN === NaN);          // false!!
console.log(0 / 0);                // NaN
console.log("abc" * 2);            // NaN
console.log(Number("abc"));        // NaN

// Detecting NaN correctly
console.log(Number.isNaN(NaN));    // true — the reliable way
console.log(isNaN("abc"));         // true — but isNaN() coerces first, so it's less strict
console.log(Number.isNaN("abc"));  // false — "abc" is not NaN itself, it's a non-numeric string

Other Numeric Edge Cases

console.log(0.1 + 0.2);              // 0.30000000000000004 — floating point imprecision
console.log(0.1 + 0.2 === 0.3);       // false!
console.log(Number.MAX_SAFE_INTEGER); // 9007199254740991
console.log(1 / 0);                   // Infinity
console.log(-1 / 0);                  // -Infinity
console.log(Object.is(NaN, NaN));     // true — Object.is treats NaN as equal to itself
console.log(Object.is(0, -0));        // false — but distinguishes +0 from -0 (unlike ===)
💡 Tip: Never compare floating-point numbers with === when precision matters. Instead check if the difference is smaller than a tiny tolerance: Math.abs(a - b) < Number.EPSILON.

ADVANCED9. Common Pitfalls

1. Confusing null and undefined

let a;          // undefined — JS did this
let b = null;   // null — YOU did this on purpose

console.log(a == b);   // true (loose — both are "nothing")
console.log(a === b);  // false (strict — different types)

2. Array/Object typeof Confusion

function isPlainObject(val) {
    return typeof val === "object" && val !== null && !Array.isArray(val);
}
console.log(isPlainObject([]));   // false — correctly excludes arrays
console.log(isPlainObject(null)); // false — correctly excludes null
console.log(isPlainObject({}));   // true

3. String Numbers From User Input

const input = "42";        // HTML inputs always give strings
console.log(input + 1);   // "421" — string concatenation, not addition!
console.log(Number(input) + 1); // 43 — correct after explicit conversion

4. BigInt vs Number Mixing

const big = 10n;
const small = 5;
// console.log(big + small);  // ❌ TypeError
console.log(big + BigInt(small)); // ✅ 15n

INTERMEDIATE10. Best Practices

1. Prefer === and !== over == and !=

// ✅ Predictable
if (value === 5) { }

// ❌ Coercion surprises
if (value == "5") { } // true for value = 5, but also weird edge cases

2. Convert Types Explicitly

const qty = Number(formInput.value);
if (Number.isNaN(qty)) {
    throw new Error("Invalid input");
}

3. Use Number.isNaN, Not Global isNaN

Number.isNaN("hello");  // false — correctly does not coerce first
isNaN("hello");          // true  — coerces "hello" to NaN first, then checks

4. Use Array.isArray to Detect Arrays

Array.isArray(value); // reliable
// typeof value === "object" is NOT enough — it's also true for arrays

5. Check for null/undefined Together When Appropriate

if (value == null) { /* catches both null and undefined */ }
// equivalent, more explicit alternative:
if (value === null || value === undefined) { }

6. Guard Against NaN Propagation

function safeDivide(a, b) {
    if (b === 0) return null;
    const result = a / b;
    return Number.isNaN(result) ? null : result;
}

📋 Quick Reference Summary

Concept Key Points
Primitives string, number, boolean, undefined, null, bigint, symbol. Immutable, compared by value.
Reference types Object, Array, Function, Date, Map, Set. Mutable, compared by reference.
typeof quirks typeof null === "object" (bug); arrays are "object" too — use Array.isArray().
Coercion Implicit happens automatically (can surprise you); explicit (Number(), String()) is safer.
Falsy values Exactly 6: false, 0, "", null, undefined, NaN. Everything else, including [] and {}, is truthy.
NaN Not equal to itself. Detect with Number.isNaN(), never === NaN.
