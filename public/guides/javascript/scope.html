BEGINNER1. What is Scope?

Scope determines WHERE in your code a variable is visible and accessible. JavaScript has three scope levels: global, function, and block.

Real-world analogy: Scope is like a building with nested rooms. The global scope is the lobby — everyone can see it. A function is a private office — only people inside can access what's there. A block is a mini-closet inside the office. 
const globalVar = "I'm everywhere";

function myFunction() {
    const functionVar = "I'm only in this function";
    if (true) {
        const blockVar = "I'm only in this block";
        console.log(blockVar); // works
    }
    // console.log(blockVar); // ❌ ReferenceError — out of scope here
}

BEGINNER2. Global Scope

Variables declared outside of any function or block belong to the global scope and can be accessed from anywhere in the program.

const appName = "Mastery Lab"; // global

function showApp() {
    console.log(appName); // accessible — reaches out to global scope
}

showApp(); // "Mastery Lab"
console.log(appName); // "Mastery Lab"
⚠️ Accidental Globals: Assigning to a variable WITHOUT var/let/const inside a function creates an accidental global (in non-strict mode) — a common and hard-to-trace source of bugs. 
function leaky() {
    leakedVar = "oops"; // no declaration keyword — becomes global!
}
leaky();
console.log(leakedVar); // "oops" — accessible from OUTSIDE the function!

// 'use strict' at the top of a file/function prevents this and throws instead

BEGINNER3. Function Scope

Variables declared with var (or any variable declared with a parameter/let/const directly inside a function body) are scoped to the ENTIRE enclosing function — accessible anywhere inside it, including nested blocks.

function calculate() {
    var result = 0;      // function-scoped

    if (true) {
        var result2 = 10; // var IGNORES the if-block — still function-scoped!
    }

    console.log(result);  // 0
    console.log(result2); // 10 — accessible even though declared inside the if block
}
calculate();
// console.log(result); // ❌ ReferenceError — not accessible outside the function

BEGINNER4. Block Scope

A block is any code between curly braces {} — if, for, while, or even a bare {}. let and const are confined to the block they're declared in.

if (true) {
    let blockScoped = "only visible in this block";
    const alsoBlockScoped = "same here";
    console.log(blockScoped); // works
}
// console.log(blockScoped);     // ❌ ReferenceError
// console.log(alsoBlockScoped); // ❌ ReferenceError
var — leaks out of blocks: 
for (var i = 0; i < 3; i++) {
    // loop body
}
console.log(i); // 3 — i survives the loop!
let — stays confined: 
for (let j = 0; j < 3; j++) {
    // loop body
}
// console.log(j); // ❌ ReferenceError

INTERMEDIATE5. The Scope Chain

When JavaScript can't find a variable in the current scope, it looks OUTWARD through each enclosing scope until it reaches the global scope. This lookup path is called the scope chain. Inner scopes can read outer variables, but never the reverse.

const level1 = "global";

function outer() {
    const level2 = "outer function";

    function inner() {
        const level3 = "inner function";

        console.log(level3); // ✅ found in inner's own scope
        console.log(level2); // ✅ found by looking up to outer
        console.log(level1); // ✅ found by looking all the way up to global
    }

    inner();
    // console.log(level3); // ❌ ReferenceError — inner's scope is not visible to outer
}

outer();
💡 Tip: The scope chain is determined by WHERE a function is physically WRITTEN in the code (lexical scoping), not by where or how it's later called. This is why it's also called "static scoping."

INTERMEDIATE6. Variable Shadowing

Shadowing happens when an inner scope declares a variable with the SAME name as one in an outer scope. The inner variable "shadows" (hides) the outer one — for code inside that inner scope only.

let color = "blue"; // global

function paint() {
    let color = "red"; // shadows the global 'color' — only inside paint()
    console.log(color); // "red"
}

paint();
console.log(color); // "blue" — global 'color' is completely unaffected
⚠️ Confusing Shadowing: Shadowing the SAME name across nested scopes makes code harder to read — it's not always obvious which "color" a given line refers to. Prefer distinct names when possible. 
// Illegal shadowing: can't re-declare a let with var in the same scope
let x = 1;
// var x = 2; // ❌ SyntaxError: Identifier 'x' has already been declared

// But a var CAN be shadowed by a let in an inner block — perfectly legal
var y = 1;
if (true) {
    let y = 2; // fine — different scope
    console.log(y); // 2
}
console.log(y); // 1

ADVANCED7. Hoisting

Hoisting is JavaScript's behavior of processing declarations before executing code line by line. Different declaration types are hoisted differently.

// var — hoisted AND initialized with undefined
console.log(a); // undefined (not an error!)
var a = 5;
console.log(a); // 5

// Function declarations — FULLY hoisted (name + body)
sayHi(); // "Hi!" — works even though called before the definition
function sayHi() {
    console.log("Hi!");
}

// Function EXPRESSIONS are not fully hoisted — only the variable declaration is
// greet(); // ❌ TypeError: greet is not a function
var greet = function() {
    console.log("Hello");
};
Mental model: JavaScript effectively splits var x = 5; into two steps: the declaration (var x;) is moved to the top of its scope, but the assignment (x = 5;) stays exactly where it was written.

ADVANCED8. The Temporal Dead Zone (TDZ)

let and const ARE hoisted (unlike the popular myth that they aren't) — but they are NOT initialized. The span between the start of the scope and the actual declaration line is called the Temporal Dead Zone: accessing the variable there throws a ReferenceError.

console.log(typeof x); // "undefined" — var, hoisted with a default value
var x = 5;

// console.log(y); // ❌ ReferenceError: Cannot access 'y' before initialization
let y = 10; // y is in the TDZ until this line runs

function demo() {
    // TDZ for 'z' starts here
    console.log(z); // ❌ ReferenceError
    let z = 1;      // TDZ for 'z' ends here
}
💡 Tip: The TDZ is actually a SAFETY feature — it turns a class of "used a variable before it made sense" bugs into an immediate, loud error instead of a silent undefined that only manifests as unexpected behavior later.

ADVANCED9. Common Pitfalls

1. var in Loops with Closures

// ❌ All callbacks share ONE function-scoped i
const fns = [];
for (var i = 0; i < 3; i++) {
    fns.push(() => console.log(i));
}
fns[0](); // 3 (not 0!) — by the time it runs, the loop already finished, i === 3

// ✅ let creates a fresh binding PER iteration
const fixed = [];
for (let i = 0; i < 3; i++) {
    fixed.push(() => console.log(i));
}
fixed[0](); // 0

2. Assuming Block Scope for var

if (true) {
    var leaked = "I escape the block";
}
console.log(leaked); // "I escape the block" — surprising if you expected block scope

3. Relying on Hoisting for Readability

// Technically works, but confusing to read
console.log(total); // undefined
calculate();
var total;
function calculate() { total = 100; }

// ✅ Much clearer — declare before use
let total2;
function calculate2() { total2 = 100; }
calculate2();
console.log(total2);

4. Global Namespace Pollution

// ❌ Many loose globals collide easily across scripts
var currentUser = "Alice";
var currentPage = "home";

// ✅ Namespace under one object, or use ES modules
const AppState = { currentUser: "Alice", currentPage: "home" };

INTERMEDIATE10. Best Practices

1. Default to const, Use let When Reassignment Is Needed

// ✅ Signals intent clearly
const MAX_RETRIES = 3;
let attempts = 0;
attempts++;

2. Avoid var Entirely in Modern Code

// ✅ Block scoping avoids leaks and closure bugs
for (let i = 0; i < items.length; i++) { }

// ❌ Legacy, function-scoped, hoists oddly
for (var i = 0; i < items.length; i++) { }

3. Declare Variables at the Top of Their Scope

// ✅ No ambiguity about hoisting/TDZ
function process(data) {
    let result = null;
    let errors = [];
    // ... rest of the logic
}

4. Minimize Global Variables

// ✅ Wrap related state in a module/object/closure
const Counter = (() => {
    let count = 0;
    return { increment: () => ++count, get: () => count };
})();

5. Avoid Shadowing When It Hurts Readability

// ✅ Distinct names avoid ambiguity
function processUser(user) {
    const userId = user.id;
}

// ❌ Shadowed name at multiple levels is confusing
function processUser(user) {
    const user2 = { ...user, verified: true }; // should just pick a clearer name than reusing 'user'
}

📋 Quick Reference Summary

Concept Key Points
Global scope Accessible everywhere; avoid polluting it with loose variables.
Function scope var is confined to the nearest function, ignoring inner blocks.
Block scope let/const are confined to their {}.
Scope chain Lookup travels outward — inner → enclosing → global — stops at first match.
Hoisting var hoists as undefined; functions hoist fully; let/const hoist into the TDZ.
TDZ Accessing let/const before their declaration line throws ReferenceError.
