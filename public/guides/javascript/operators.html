BEGINNER1. What is an Operator?

An operator is a symbol that performs an operation on one or more values, called operands. a + b has two operands (a and b) joined by the + operator.

Real-world analogy: Operators are tools in a toolbox. A hammer (+) drives nails. A measuring tape (===) checks if two lengths match exactly. Each tool has one job — using the wrong one causes problems.

Types of Operators

  • Arithmetic: + - * / % **
  • Comparison: === !== > < >= <=
  • Logical: && || ! ??
  • Assignment: = += -= *= /=
  • Ternary (conditional): ? :

Unary vs Binary

// Unary — one operand
-5;          // negation
!true;       // logical NOT
typeof 42;   // type check

// Binary — two operands
5 + 3;
a && b;

// Ternary — three operands (the only one!)
condition ? a : b;

BEGINNER2. Arithmetic Operators

10 + 3;   // 13 — addition
10 - 3;   // 7  — subtraction
10 * 3;   // 30 — multiplication
10 / 3;   // 3.333... — division
10 % 3;   // 1  — remainder (modulo)
10 ** 3;  // 1000 — exponentiation (10 to the power of 3)

The + Operator Is Special

Unlike other arithmetic operators, + also means string concatenation. If either operand is a string, JavaScript concatenates instead of adding.

5 + 3;         // 8   — both numbers, adds
"5" + 3;       // "53" — string wins, concatenates
5 + "3";       // "53" — same, order doesn't matter
5 + 3 + "!";   // "8!" — left to right: 5+3=8, then 8+"!"="8!"
"5" + 3 + 3;   // "533" — left to right: "5"+3="53", then "53"+3="533"

Increment / Decrement

let x = 5;
x++;           // post-increment: use x, THEN add 1 → x becomes 6
console.log(x); // 6

let y = 5;
console.log(++y); // pre-increment: add 1 FIRST, then use y → 6
console.log(y);   // 6

let a = 5;
console.log(a++); // 5 (returns old value, then increments)
console.log(a);   // 6
💡 Tip: % (modulo) is one of the most practically useful operators — it's how you check "is this number even?" (n % 2 === 0), wrap around an array index, or detect every Nth item.

BEGINNER3. Comparison Operators

JavaScript has two flavors of equality: strict (===/!==) which checks type AND value, and loose (==/!=) which coerces types before comparing.

Expression Result Why
5 === 5trueSame type, same value
5 === "5"falseDifferent types — strict blocks coercion
5 == "5"trueLoose equality coerces "5" to 5 first
null == undefinedtrueSpecial case: these two are loosely equal to each other only
null === undefinedfalseDifferent types under strict comparison
NaN === NaNfalseNaN is never equal to anything, including itself
⚠️ Common Pitfall: Always prefer ===/!== over ==/!=. Loose equality has confusing edge cases like "" == 0 being true and [] == false being true. The one common exception is value == null to check for both null and undefined at once. 
5 > 3;    // true
5 < 3;    // false
5 >= 5;   // true
5 <= 4;   // false

"apple" < "banana"; // true — strings compare lexicographically (dictionary order)
"10" < "9";          // true! — string comparison, not numeric ("1" < "9" character-wise)

INTERMEDIATE4. Logical Operators & Short-Circuiting

Logical operators don't just return true/false — they return one of their actual operands, based on short-circuit evaluation.

&& (AND) — Stops at First Falsy

true && "hello";    // "hello" — left was truthy, so returns right
false && "hello";   // false    — left was falsy, stops immediately, right never evaluated
0 && expensiveCall(); // 0      — expensiveCall() is NEVER called!

// Common pattern: guard before running code
isLoggedIn && showDashboard();  // showDashboard() only runs if isLoggedIn is truthy

|| (OR) — Stops at First Truthy

false || "fallback";  // "fallback" — left was falsy, returns right
"hi" || "fallback";   // "hi"       — left was truthy, stops immediately
0 || "default";       // "default" — 0 is falsy, so it's replaced too (see pitfall below!)

! (NOT)

!true;      // false
!0;         // true  — 0 is falsy, so !0 is true
!!"hello";  // true  — double-negation is a common trick to force a real boolean
!!"";       // false
⚠️ Common Pitfall — The || Fallback Trap: settings.volume || 10 looks like "use volume, or default to 10" — but if volume is legitimately 0 (silent), || treats it as falsy and replaces it with 10 anyway! This is exactly the problem ?? (Section 5) was created to solve. 
const settings = { volume: 0 };
settings.volume || 10;   // 10  — wrong! 0 is a valid volume, got overridden
settings.volume ?? 10;   // 0   — correct! ?? only replaces null/undefined

INTERMEDIATE5. Nullish Coalescing (??)

The nullish coalescing operator (??) returns its right-hand side ONLY when the left-hand side is null or undefined — never for other falsy values like 0, "", or false.

0 ?? "default";          // 0          — 0 is not nullish, kept as-is
"" ?? "default";         // ""         — empty string kept
false ?? "default";      // false      — kept
null ?? "default";       // "default"  — null IS nullish
undefined ?? "default";  // "default"  — undefined IS nullish
|| (OR) — replaces ANY falsy value: 
function getVolume(v) {
    return v || 50;
}
getVolume(0);   // 50 — bug! 0 got replaced
getVolume(null); // 50 — intended
?? (nullish) — replaces ONLY null/undefined: 
function getVolume(v) {
    return v ?? 50;
}
getVolume(0);    // 0  — correct! 0 is kept
getVolume(null); // 50 — intended

Nullish Coalescing Assignment (??=)

const config = { theme: null };
config.theme ??= "light";  // only assigns if theme is null/undefined
console.log(config.theme); // "light"

config.theme ??= "dark";   // theme is already "light", so nothing changes
console.log(config.theme); // "light"
⚠️ Syntax Restriction: You cannot directly mix ?? with && or || without parentheses — a || b ?? c throws a SyntaxError. Always parenthesize: (a || b) ?? c.

BEGINNER6. Assignment Operators

Compound assignment operators combine an operation with assignment — x += 5 is shorthand for x = x + 5.

let score = 50;
score += 10;   // score = score + 10  → 60
score -= 5;    // score = score - 5   → 55
score *= 2;    // score = score * 2   → 110
score /= 10;   // score = score / 10  → 11
score **= 2;   // score = score ** 2  → 121
score %= 5;    // score = score % 5   → 1

Logical Assignment Operators (Modern)

let a = null;
a ??= "default";   // assign only if a is null/undefined → "default"

let b = 0;
b ||= 100;         // assign only if b is falsy → 100

let c = "existing";
c &&= "replaced";  // assign only if c is truthy → "replaced"

INTERMEDIATE7. The Ternary Operator

The ternary (conditional) operator is the only operator that takes three operands: condition ? valueIfTrue : valueIfFalse. It's a compact expression form of if/else.

const age = 20;
const label = age >= 18 ? "adult" : "minor";
console.log(label); // "adult"

// Equivalent if/else:
let label2;
if (age >= 18) {
    label2 = "adult";
} else {
    label2 = "minor";
}

Chaining Ternaries (Use Sparingly)

const score = 75;
const grade = score >= 90 ? "A"
            : score >= 80 ? "B"
            : score >= 70 ? "C"
            : "F";
console.log(grade); // "C"
⚠️ Readability Warning: Chained ternaries beyond 2-3 levels become hard to read. For more than a couple of branches, prefer if/else if or a lookup object/switch statement instead.

ADVANCED8. Operator Precedence

When an expression has multiple operators, precedence determines the order they're evaluated. Multiplication/division happen before addition/subtraction, just like in math class.

2 + 3 * 4;      // 14, not 20 — * has higher precedence than +
(2 + 3) * 4;    // 20 — parentheses override precedence

10 > 5 && 3 < 1;  // false — comparisons happen before &&
true || false && false; // true — && binds tighter than ||, evaluates as: true || (false && false)

let x = 5;
let y = x++ + ++x;  // x++ returns 5 (then x=6), ++x returns 7 (x=7 first)
console.log(y);     // 12
console.log(x);     // 7
Precedence (high → low) Operators
1() grouping
2++ -- ! (unary)
3** (exponent)
4* / %
5+ -
6< <= > >=
7=== !== == !=
8&&
9|| ??
10? : (ternary)
11= += -= ... (assignment)
💡 Tip: You don't need to memorize this whole table. When in doubt, add parentheses — they cost nothing and make intent explicit for the next reader (including future you).

ADVANCED9. Other Useful Operators

Optional Chaining (?.)

const user = { address: null };
console.log(user.address?.city);   // undefined — no error, even though address is null
console.log(user.contact?.phone);  // undefined — safe even if contact doesn't exist at all
user.greet?.();                    // calls greet() only if it exists

Comma Operator

// Evaluates each expression, returns the LAST one — rarely used, mostly in for loops
for (let i = 0, j = 10; i < j; i++, j--) {
    console.log(i, j);
}

Spread Operator (...)

const arr = [1, 2, 3];
const copy = [...arr, 4, 5];  // [1, 2, 3, 4, 5]

const obj = { a: 1 };
const merged = { ...obj, b: 2 }; // { a: 1, b: 2 }

function sum(a, b, c) { return a + b + c; }
console.log(sum(...arr)); // 6 — spreads array as individual arguments

typeof and instanceof

typeof "hi";              // "string"
[] instanceof Array;      // true
new Date() instanceof Date; // true

INTERMEDIATE10. Best Practices

1. Always Use === and !==

// ✅ Good
if (status === "active") { }

// ❌ Avoid
if (status == "active") { }

2. Use ?? Instead of || for Defaults With Numbers/Booleans

// ✅ Correct for numeric/boolean defaults
const timeout = options.timeout ?? 3000;

// ❌ Buggy if timeout could legitimately be 0
const timeout = options.timeout || 3000;

3. Parenthesize Mixed Logical Expressions

// ✅ Clear intent
if ((isAdmin || isModerator) && isActive) { }

// ❌ Ambiguous to read at a glance
if (isAdmin || isModerator && isActive) { }

4. Avoid Chained Ternaries Beyond 2 Levels

// ✅ Readable
function getGrade(score) {
    if (score >= 90) return "A";
    if (score >= 80) return "B";
    return "C";
}

// ❌ Hard to scan
const grade = score >= 90 ? "A" : score >= 80 ? "B" : "C";

5. Use Logical Assignment for Concise Defaults

// ✅ Modern and concise
config.retries ??= 3;

// Instead of
if (config.retries === null || config.retries === undefined) {
    config.retries = 3;
}
