BEGINNER1. What is a Loop?

A loop repeats a block of code as long as a condition remains true, avoiding the need to copy-paste the same statement over and over.

Real-world analogy: A loop is like a washing machine cycle. It keeps spinning until the timer reaches zero. break is the emergency stop button. continue is skipping one step and moving straight to the next.

The Five Loop Forms

  • for — when you know how many times to repeat
  • while — repeat while a condition holds, checked BEFORE each run
  • do...while — like while, but checked AFTER — runs at least once
  • for...of — iterate over the VALUES of an iterable (arrays, strings, Maps, Sets)
  • for...in — iterate over the KEYS of an object

BEGINNER2. The for Loop

The classic for loop has three parts separated by semicolons: initialization, condition, and update.

for (let i = 0; i < 3; i++) {
    console.log(i);
}
// Output: 0  1  2

// Anatomy:
// for ( INIT ; CONDITION ; UPDATE ) { BODY }
//       let i=0   i<3       i++

Counting Down

for (let i = 5; i > 0; i--) {
    console.log(i);
}
// Output: 5 4 3 2 1

Stepping by More Than 1

for (let i = 0; i <= 10; i += 2) {
    console.log(i);
}
// Output: 0 2 4 6 8 10

Nested Loops

for (let i = 1; i <= 3; i++) {
    for (let j = 1; j <= 3; j++) {
        console.log(`${i}-${j}`);
    }
}
// Output: "1-1" "1-2" "1-3" "2-1" "2-2" "2-3" "3-1" "3-2" "3-3"
💡 Tip: Always declare the loop counter with let, not var. let gives each iteration its own binding, which matters a great deal once closures are involved (see Section 9).

BEGINNER3. while and do...while

Use while when you don't know in advance how many iterations you'll need — you just keep going until a condition becomes false.

let n = 3;
while (n > 0) {
    console.log(n);
    n--;
}
// Output: 3 2 1

do...while — Runs At Least Once

do...while checks its condition AFTER running the body, guaranteeing at least one execution — useful for things like "keep asking until valid input."

let attempts = 0;
do {
    attempts++;
    console.log("Attempt", attempts);
} while (attempts < 3);
// Output: "Attempt 1" "Attempt 2" "Attempt 3"

// Even if the condition starts false, the body still runs once:
let x = 10;
do {
    console.log("ran"); // "ran" — this DOES print
} while (x < 5);
⚠️ Infinite Loop Danger: If you forget to update the condition variable inside a while loop, it never becomes false — the loop runs forever and freezes your program (or browser tab). 
// ❌ INFINITE LOOP — n is never decremented
let n = 5;
while (n > 0) {
    console.log(n);
    // forgot: n--;
}

BEGINNER4. for...of (Iterating Values)

for...of iterates over the actual VALUES of any iterable — arrays, strings, Maps, Sets, and more.

const fruits = ["apple", "banana", "cherry"];
for (const fruit of fruits) {
    console.log(fruit);
}
// Output: "apple" "banana" "cherry"

// Works on strings too — iterates characters
for (const char of "abc") {
    console.log(char);
}
// Output: "a" "b" "c"

// Works on Map — [key, value] pairs
const scores = new Map([["alice", 90], ["bob", 75]]);
for (const [name, score] of scores) {
    console.log(name, score);
}
// Output: "alice" 90   "bob" 75

Getting the Index Too

const items = ["a", "b", "c"];
for (const [index, value] of items.entries()) {
    console.log(index, value);
}
// Output: 0 "a"   1 "b"   2 "c"

INTERMEDIATE5. for...in (Iterating Keys)

for...in iterates over the ENUMERABLE KEYS of an object (including inherited ones). It's meant for plain objects, not arrays.

const person = { name: "Alice", age: 30, city: "NYC" };

for (const key in person) {
    console.log(key, person[key]);
}
// Output: "name" "Alice"   "age" 30   "city" "NYC"
⚠️ Don't Use for...in on Arrays: On an array, for...in gives you STRING INDICES ("0", "1", "2"), not values — and it can also pick up inherited/non-index properties. Always use for...of or array methods for arrays instead. 
const arr = ["x", "y", "z"];

for (const key in arr) {
    console.log(key, typeof key); // "0" "string", "1" "string", "2" "string"
}

for (const val of arr) {
    console.log(val); // "x", "y", "z" — this is what you actually want
}
Loop Iterates over Use it for
for...ofValuesArrays, strings, Maps, Sets
for...inKeysPlain objects

INTERMEDIATE6. break and continue

break exits the loop entirely — no further iterations run. continue skips only the REST of the current iteration and jumps to the next one.

break

for (let i = 0; i < 10; i++) {
    if (i === 3) break;
    console.log(i);
}
// Output: 0 1 2  (stops entirely once i reaches 3)

continue

for (let i = 0; i < 6; i++) {
    if (i % 2 === 0) continue; // skip even numbers
    console.log(i);
}
// Output: 1 3 5

Finding an Item (break as a Shortcut)

const users = [{id:1}, {id:2}, {id:3}];
let found = null;

for (const user of users) {
    if (user.id === 2) {
        found = user;
        break; // stop searching once found — no need to check the rest
    }
}
console.log(found); // {id: 2}

ADVANCED7. Labeled Loops

A label lets break or continue target an OUTER loop from inside a nested loop — otherwise they only affect the innermost loop.

outer: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (j === 1) break outer; // exits BOTH loops immediately
        console.log(i, j);
    }
}
// Output: 0 0   (then stops entirely — outer loop is also exited)
// Without the label, break only exits the inner loop:
for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (j === 1) break; // only exits the inner "j" loop
        console.log(i, j);
    }
}
// Output: 0 0   1 0   2 0  (outer loop keeps going)
💡 Tip: Labeled loops are rare in modern code. Most of the time, extracting the nested loops into a separate function and using a plain return to escape both levels is clearer.

ADVANCED8. Loops vs Array Methods

Modern JavaScript often prefers array methods (map, filter, forEach, reduce) over manual loops for readability — but each has trade-offs.

Manual for loop: 
const doubled = [];
for (let i = 0; i < nums.length; i++) {
    doubled.push(nums[i] * 2);
}
Array method (map): 
const doubled = nums.map(n => n * 2);
Situation Prefer
Transforming every element into a new arraymap
Need to break early / stop searchingfor or for...of (array methods can't break)
Async operations that need sequential awaitfor...of (not forEach — see pitfalls)
Simple "do this for each item"forEach or for...of

ADVANCED9. Common Pitfalls

1. The Classic var-in-Loop Closure Bug

// ❌ BUG: all callbacks share the SAME var i
const callbacks = [];
for (var i = 0; i < 3; i++) {
    callbacks.push(() => console.log(i));
}
callbacks[0](); // 3 (not 0!)
callbacks[1](); // 3 (not 1!)
callbacks[2](); // 3 (not 2!)

// ✅ FIX: let creates a NEW binding for each iteration
const fixed = [];
for (let i = 0; i < 3; i++) {
    fixed.push(() => console.log(i));
}
fixed[0](); // 0
fixed[1](); // 1
fixed[2](); // 2

2. forEach Does Not Await Async Callbacks

// ❌ WRONG — forEach fires all callbacks without waiting
async function processAll(ids) {
    ids.forEach(async (id) => {
        await process(id); // forEach doesn't care about this promise!
    });
    console.log("Done"); // logs BEFORE processing actually finishes
}

// ✅ CORRECT — for...of properly awaits each iteration
async function processAll(ids) {
    for (const id of ids) {
        await process(id);
    }
    console.log("Done"); // logs only after all are processed
}

3. Modifying an Array While Looping Over It

const arr = [1, 2, 3, 4];
// ❌ Removing items while iterating shifts indices, skips elements
for (let i = 0; i < arr.length; i++) {
    if (arr[i] % 2 === 0) arr.splice(i, 1); // BUG: skips the item after the removed one
}

// ✅ Iterate backwards, or use filter to build a new array
const filtered = arr.filter(n => n % 2 !== 0);

4. off-by-one Errors

const arr = [10, 20, 30];
// ❌ i <= arr.length reads one index too far
for (let i = 0; i <= arr.length; i++) {
    console.log(arr[i]); // last iteration logs undefined
}
// ✅ Correct bound
for (let i = 0; i < arr.length; i++) {
    console.log(arr[i]);
}

INTERMEDIATE10. Best Practices

1. Use let, Never var, for Loop Counters

// ✅ Good
for (let i = 0; i < 10; i++) { }

// ❌ Avoid — leaks scope, breaks closures
for (var i = 0; i < 10; i++) { }

2. Prefer for...of Over Index-Based Loops When You Don't Need the Index

// ✅ Cleaner
for (const item of items) { console.log(item); }

// Only reach for index-based when you actually need i
for (let i = 0; i < items.length; i++) { console.log(i, items[i]); }

3. Cache Length in Very Hot Loops (Micro-Optimization)

// Rarely necessary in modern engines, but occasionally seen:
const len = arr.length;
for (let i = 0; i < len; i++) { }

4. Never Use for...in on Arrays

// ✅ Correct
for (const item of arr) { }

// ❌ Wrong tool — gives string indices, may include extras
for (const key in arr) { }

5. Extract Complex Loop Bodies Into Named Functions

// ✅ Readable
for (const order of orders) {
    processOrder(order);
}

function processOrder(order) {
    // ...validation, calculation, side effects
}

📋 Quick Reference Summary

Concept Key Points
for Known iteration count. Three parts: init; condition; update.
while / do...while Condition-driven. do...while always runs at least once.
for...of Iterates VALUES of arrays, strings, Maps, Sets.
for...in Iterates KEYS of plain objects — avoid on arrays.
break / continue break exits the loop; continue skips to the next iteration.
let vs var in loops let gives each iteration its own binding — essential for correct closures.
