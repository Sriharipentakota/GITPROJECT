BEGINNER1. What are Variables?

Definition

A variable is a named container that stores a value. Think of it as a labeled box where you can put data and retrieve it later by using the label (variable name).

Real-world analogy: A variable is like a mailbox with a name on it. You can put messages in the mailbox and retrieve them by calling the mailbox by its name.

Why do we need variables?

  • Store data: Keep information for later use
  • Reusability: Use the same value multiple times without retyping
  • Maintainability: Easy to update values in one place
  • Readability: Give meaningful names to values

Creating Your First Variable

// Basic variable declaration and initialization
let age = 25;
console.log(age);  // Output: 25

// Update the variable
age = 26;
console.log(age);  // Output: 26
💡 Tip: In modern JavaScript, you'll mostly use let and const. We'll explain why later!

BEGINNER2. Declaring Variables (var, let, const)

JavaScript has three ways to declare variables: var, let, and const. Each has different characteristics.

var - The Old Way

var name = "John";
console.log(name);  // Output: John

name = "Jane";
console.log(name);  // Output: Jane

var is the oldest way to declare variables in JavaScript, but it has some quirks that make it less preferred in modern code.

Feature var let const
Can be redeclared ✅ Yes ❌ No ❌ No
Can be reassigned ✅ Yes ✅ Yes ❌ No
Scope Function scope Block scope Block scope
Hoisted ✅ Yes (with undefined) ✅ Yes (Temporal Dead Zone) ✅ Yes (Temporal Dead Zone)

let - The Modern Alternative

let color = "red";
console.log(color);  // Output: red

color = "blue";      // OK - reassignment is allowed
console.log(color);  // Output: blue

// let color = "green";  // ❌ ERROR - cannot redeclare
When to use let: When you need a variable that will change value. This is your default choice in modern JavaScript.

const - The Constant

const PI = 3.14159;
console.log(PI);     // Output: 3.14159

// PI = 3.14;       // ❌ ERROR - cannot reassign
// const PI = 3.14; // ❌ ERROR - cannot redeclare

const with Objects (Important!)

const prevents reassignment, but NOT mutation of objects:

const person = {
    name: "Alice",
    age: 30
};

// ✅ This is ALLOWED - modifying object properties
person.name = "Bob";
person.age = 31;
console.log(person);  // Output: { name: 'Bob', age: 31 }

// ❌ This is NOT ALLOWED - reassigning the entire object
// person = { name: "Charlie", age: 25 };
When to use const: By default, use const. Use let only when you know the variable will be reassigned. Avoid var.

Comparison Example

var (Outdated): 
var x = 10;
var x = 20;  // Allowed
x = 30;      // Allowed
console.log(x);  // 30
let (Modern): 
let x = 10;
// let x = 20;  // Error!
x = 30;      // Allowed
console.log(x);  // 30

INTERMEDIATE3. Variable Scope

Scope determines where a variable can be accessed in your code. JavaScript has different types of scopes.

Global Scope

Variables declared outside of any function or block are in the global scope and can be accessed anywhere.

const globalVar = "I'm global";

function testGlobal() {
    console.log(globalVar);  // Output: I'm global
}

testGlobal();
console.log(globalVar);  // Output: I'm global

Function Scope (with var)

function myFunction() {
    var functionVar = "I'm local to this function";
    console.log(functionVar);  // Works fine
}

myFunction();
// console.log(functionVar);  // ❌ Error: functionVar is not defined

Block Scope (with let and const)

A block is any code enclosed in curly braces {}. This includes if statements, loops, etc.

if (true) {
    let blockVar = "I'm inside a block";
    const blockConst = "Also inside a block";
    console.log(blockVar);  // Works
}

// console.log(blockVar);   // ❌ Error: blockVar is not defined
// console.log(blockConst); // ❌ Error: blockConst is not defined

Lexical Scope (Scope Chain)

Inner scopes can access outer scopes, but not vice versa.

const outerVar = "outer";

function outer() {
    const outerFuncVar = "outer function";
    
    function inner() {
        const innerVar = "inner";
        
        console.log(innerVar);      // ✅ Can access inner
        console.log(outerFuncVar);  // ✅ Can access parent
        console.log(outerVar);      // ✅ Can access global
    }
    
    inner();
    // console.log(innerVar);  // ❌ Cannot access inner scope
}

outer();

var vs let/const Scope - Critical Difference

// With var - function scope
function test1() {
    for (var i = 0; i < 3; i++) {
        // i is accessible here
    }
    console.log(i);  // Output: 3 (i is still accessible!)
}

// With let - block scope
function test2() {
    for (let j = 0; j < 3; j++) {
        // j is accessible here
    }
    // console.log(j);  // ❌ Error: j is not defined
}

test1();
test2();
⚠️ Common Pitfall: Using var in loops can cause unexpected behavior. This is a major reason to use let instead.

INTERMEDIATE4. Hoisting

Hoisting is JavaScript's behavior of moving declarations to the top of their scope before execution.

var Hoisting

When var is hoisted, it's initialized with undefined:

console.log(x);  // Output: undefined (not an error!)
var x = 5;
console.log(x);  // Output: 5

// JavaScript interprets this as:
// var x;              // Declaration hoisted
// console.log(x);     // undefined
// x = 5;              // Assignment stays in place
// console.log(x);     // 5

let and const Hoisting

let and const are hoisted but not initialized. This creates the Temporal Dead Zone (TDZ):

// ❌ ReferenceError: Cannot access 'y' before initialization
console.log(y);
let y = 5;

// JavaScript's view:
// TDZ starts here
// let y;  // Declaration hoisted, but not initialized
// console.log(y);  // ❌ Still in TDZ
// y = 5;
// TDZ ends here

Function Hoisting

Function declarations are completely hoisted (both declaration and definition):

// ✅ This works! Function is fully hoisted
sayHello();  // Output: Hello!

function sayHello() {
    console.log("Hello!");
}

// BUT function expressions are NOT hoisted
// greet();  // ❌ Error: greet is not a function
const greet = function() {
    console.log("Hi!");
};

Hoisting Visualization

What you write: 
console.log(name);
var name = "John";
How JavaScript interprets it: 
var name;           // Hoisted declaration
console.log(name);  // undefined
name = "John";      // Assignment

BEGINNER5. Data Types Stored in Variables

JavaScript variables can store different types of data. Let's explore them all.

Primitive Data Types

Primitive types are immutable (cannot be changed) and are passed by value.

1. String

const name = "Alice";
const greeting = 'Hello';
const template = `Hello, ${name}!`;

console.log(name);       // Alice
console.log(greeting);   // Hello
console.log(template);   // Hello, Alice!

2. Number

const integer = 42;
const decimal = 3.14;
const negative = -10;
const zero = 0;

console.log(typeof 42);  // "number"

3. Boolean

const isActive = true;
const isAdmin = false;

console.log(isActive);   // true
console.log(typeof isActive);  // "boolean"

4. undefined

let x;
console.log(x);           // undefined
console.log(typeof x);    // "undefined"

5. null

let emptyValue = null;
console.log(emptyValue);      // null
console.log(typeof null);     // "object" (quirk of JavaScript)

6. BigInt

const largeNumber = 9007199254740992n;
const anotherBigInt = BigInt("12345678901234567890");

console.log(typeof largeNumber);  // "bigint"

7. Symbol (Advanced)

const sym1 = Symbol("id");
const sym2 = Symbol("id");

console.log(sym1 === sym2);  // false - each symbol is unique
console.log(typeof sym1);    // "symbol"

Object Data Types (Reference Types)

Objects are mutable and passed by reference.

Object Literal

const person = {
    name: "Bob",
    age: 30,
    city: "New York"
};

console.log(person.name);     // Bob
console.log(person["age"]);   // 30

Array

const fruits = ["apple", "banana", "cherry"];
const numbers = [1, 2, 3, 4, 5];

console.log(fruits[0]);    // apple
console.log(fruits.length);  // 3

Function

const add = function(a, b) {
    return a + b;
};

console.log(add(5, 3));  // 8

BEGINNER6. Variable Naming Conventions

Rules for Naming Variables

  • Must start with a letter, underscore (_), or dollar sign ($)
  • Can contain letters, numbers, underscores, and dollar signs
  • Cannot be a reserved keyword (if, while, const, etc.)
  • Are case-sensitive (myVar ≠ myvar)
  • Cannot contain spaces

Good vs Bad Naming

❌ Bad: 
let x = 5;
let n = "John";
let a = true;
let $$ = "value";
✅ Good: 
let userAge = 5;
let userName = "John";
let isActive = true;
let totalPrice = "value";

Naming Conventions

camelCase (Standard for Variables)

const firstName = "John";
const userAge = 25;
const isEmailVerified = true;

PascalCase (for Classes and Constructors)

class UserAccount {
    // ...
}

const user = new UserAccount();

UPPER_SNAKE_CASE (for Constants)

const MAX_USERS = 100;
const API_KEY = "abc123xyz";
const DB_HOST = "localhost";
💡 Tip: Use descriptive names that explain what the variable contains. Future you (and your team) will thank you!

INTERMEDIATE7. Primitive vs Reference Types

Primitive Types - Pass by Value

When you assign a primitive to another variable, the VALUE is copied.

let a = 5;
let b = a;

a = 10;

console.log(a);  // 10
console.log(b);  // 5 (unchanged because b got a copy of the value)

Reference Types - Pass by Reference

When you assign an object to another variable, the REFERENCE is copied, not the value.

let person1 = { name: "Alice", age: 30 };
let person2 = person1;

person1.age = 31;

console.log(person1);  // { name: 'Alice', age: 31 }
console.log(person2);  // { name: 'Alice', age: 31 } - Both point to same object!

Visual Explanation

Primitive (Value): 
let x = 10;
let y = x;
// x and y each have their own copy of 10

x = 20;  // Only x changes
// y is still 10
Reference (Object): 
let obj1 = { value: 10 };
let obj2 = obj1;
// obj1 and obj2 point to the SAME object

obj1.value = 20;  // Affects both
// obj2.value is also now 20

Creating True Copies

Shallow Copy of Objects

const original = { name: "Bob", age: 25 };

// Method 1: Spread operator
const copy1 = { ...original };

// Method 2: Object.assign()
const copy2 = Object.assign({}, original);

copy1.name = "Charlie";
console.log(original.name);  // Bob (unchanged)
console.log(copy1.name);     // Charlie

Deep Copy

const nested = {
    user: { name: "Dave", details: { age: 30 } }
};

// Shallow copy (nested objects still referenced)
const shallowCopy = { ...nested };

// Deep copy
const deepCopy = JSON.parse(JSON.stringify(nested));

deepCopy.user.details.age = 31;
console.log(nested.user.details.age);  // 30 (unaffected)

ADVANCED8. Closures

A closure is a function that has access to variables from its outer function scope, even after the outer function has returned.

Understanding Closures

function outer() {
    const message = "Hello";  // Outer function variable
    
    function inner() {
        console.log(message);  // Inner function accesses outer variable
    }
    
    return inner;
}

const myFunction = outer();
myFunction();  // Output: Hello

Practical Closure Example

function createCounter() {
    let count = 0;  // This persists due to closure
    
    return {
        increment: function() {
            count++;
            return count;
        },
        decrement: function() {
            count--;
            return count;
        },
        getCount: function() {
            return count;
        }
    };
}

const counter = createCounter();
console.log(counter.increment());  // 1
console.log(counter.increment());  // 2
console.log(counter.decrement());  // 1
console.log(counter.getCount());   // 1

Why Closures Matter

Data Privacy Pattern: 
function createBankAccount(initialBalance) {
    let balance = initialBalance;  // Private variable
    
    return {
        deposit(amount) {
            balance += amount;
            return balance;
        },
        withdraw(amount) {
            if (amount <= balance) {
                balance -= amount;
                return balance;
            }
            return "Insufficient funds";
        },
        getBalance() {
            return balance;
        }
    };
}

const myAccount = createBankAccount(1000);
console.log(myAccount.deposit(500));     // 1500
console.log(myAccount.withdraw(200));    // 1300
// console.log(myAccount.balance);  // undefined - can't access directly!

Common Closure Pitfall - Loop Variables

// ❌ Problem with var
var functions_var = [];
for (var i = 0; i < 3; i++) {
    functions_var.push(function() {
        console.log(i);
    });
}
functions_var[0]();  // 3 (not 0!)
functions_var[1]();  // 3 (not 1!)
functions_var[2]();  // 3 (not 2!)

// ✅ Solution 1: Use let (block scope)
let functions_let = [];
for (let i = 0; i < 3; i++) {
    functions_let.push(function() {
        console.log(i);
    });
}
functions_let[0]();  // 0
functions_let[1]();  // 1
functions_let[2]();  // 2

// ✅ Solution 2: IIFE (Immediately Invoked Function Expression)
var functions_iife = [];
for (var i = 0; i < 3; i++) {
    functions_iife.push((function(j) {
        return function() {
            console.log(j);
        };
    })(i));
}
functions_iife[0]();  // 0
functions_iife[1]();  // 1
functions_iife[2]();  // 2

ADVANCED9. Memory and Garbage Collection

How Variables Use Memory

Primitive values are stored directly in memory, while objects are stored as references.

// Primitive: 5 bytes of memory for the number
let age = 25;

// Reference: stores address pointing to object in memory
let person = { name: "Eve", age: 25 };

Memory Stack vs Heap

Stack (Primitives): 
let x = 5;      // Stored directly in stack
let y = 10;     // Stored directly in stack
Heap (Objects): 
let obj = { };  // Reference to object stored in stack
                        // Actual object stored in heap

Garbage Collection

JavaScript automatically removes variables that are no longer referenced.

let obj = { data: "important" };
let reference = obj;

obj = null;  // obj no longer references the object
// reference still points to it, so object remains in memory

reference = null;  // Now nothing references it
// Object is eligible for garbage collection

Memory Leaks - Variables That Won't Garbage Collect

// ❌ Common memory leak: accidental global variable
function badFunction() {
    leakyVar = "This is global!";  // No var/let/const = global!
}

badFunction();
// leakyVar persists forever in memory!

// ✅ Correct approach: explicit variable declaration
function goodFunction() {
    const safeVar = "This is local";
}

Circular References

// Modern garbage collectors handle this well
const obj1 = { name: "obj1" };
const obj2 = { name: "obj2" };

obj1.ref = obj2;
obj2.ref = obj1;  // Circular reference

// When both are no longer referenced, both are cleaned up
obj1 = null;
obj2 = null;

INTERMEDIATE10. Best Practices

1. Use const by Default

// ✅ Good: Start with const
const PI = 3.14159;
const userName = "John";
const maxAttempts = 5;

// Use let only when necessary
let counter = 0;
counter++;

// Avoid var entirely
// var oldWay = "avoid this";

2. Initialize Variables at Declaration

// ✅ Good
const name = "Alice";
let age = 30;

// ❌ Avoid
let name;
let age;
name = "Alice";
age = 30;

3. Use Meaningful Names

// ✅ Descriptive
const userEmail = "john@example.com";
const isAuthenticated = true;
const maxLoginAttempts = 5;

// ❌ Unclear
const ue = "john@example.com";
const ia = true;
const mla = 5;

4. Group Related Variables

// ✅ Good: Group related data in objects
const user = {
    name: "Bob",
    email: "bob@example.com",
    age: 28,
    isAdmin: false
};

// ❌ Messy: Scattered variables
const userName = "Bob";
const userEmail = "bob@example.com";
const userAge = 28;
const userIsAdmin = false;

5. Avoid Global Variables

// ❌ Avoid global variables
var globalCounter = 0;

function increment() {
    globalCounter++;
}

// ✅ Better: Encapsulate in function or module
const counter = (function() {
    let count = 0;
    return {
        increment: () => ++count,
        get: () => count
    };
})();

6. Be Careful with Object Mutations

// ❌ Can be problematic
const config = { timeout: 5000 };
config.timeout = 10000;  // Mutating original

// ✅ Better: Create new object
const config = { timeout: 5000 };
const newConfig = { ...config, timeout: 10000 };

7. Document Complex Variables

/**
 * Cached user data with last update timestamp
 * @type {{id: number, name: string, email: string, timestamp: number}}
 */
const cachedUser = {
    id: 1,
    name: "John",
    email: "john@example.com",
    timestamp: Date.now()
};

8. Use Destructuring

// ✅ Modern and clean
const { name, email, age } = user;
const [first, second, ...rest] = array;

// Instead of
const name = user.name;
const email = user.email;
const age = user.age;

9. Use Template Literals for Strings

// ✅ Modern approach
const greeting = `Hello, ${name}! You are ${age} years old.`;

// Instead of
const greeting = "Hello, " + name + "! You are " + age + " years old.";

10. Avoid Variable Shadowing

// ❌ Confusing: same name in different scopes
let value = "global";

function test() {
    let value = "local";  // Shadows outer value
    console.log(value);   // local
}

// ✅ Better: Use different names
let globalValue = "global";

function test() {
    let localValue = "local";
    console.log(localValue);   // local
}

📋 Quick Reference Summary

Concept Key Points
var Function scoped, hoisted with undefined, can be redeclared. Avoid in modern code.
let Block scoped, hoisted with TDZ, can be reassigned. Use when value changes.
const Block scoped, hoisted with TDZ, cannot be reassigned. Use by default.
Primitives Number, String, Boolean, undefined, null, BigInt, Symbol. Passed by value.
Objects Object, Array, Function. Passed by reference.
Scope Global, Function, Block. Inner scopes can access outer scopes.
Hoisting var hoists with undefined; let/const hoist with TDZ; functions fully hoist.
Closure Function accessing variables from outer scope after it returns.
