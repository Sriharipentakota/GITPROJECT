BEGINNER1. What is an Object?

An object is an unordered collection of key-value pairs, called properties. Keys are strings (or Symbols); values can be any type — including other objects, arrays, or functions.

Real-world analogy: An object is like a filing cabinet. Each drawer is labeled with a key and holds a document (the value). You open a drawer by its label, add new drawers, update contents, or remove a drawer entirely. 
const person = {
    name: "Alice",
    age: 25,
    isActive: true
};

console.log(person.name); // "Alice"

BEGINNER2. Creating & Accessing Properties

There are two ways to access a property: dot notation for known, valid identifier names, and bracket notation for dynamic keys or names that aren't valid identifiers.

const user = { name: "Bob", age: 30, "favorite color": "blue" };

// Dot notation — key is a literal, known in advance
user.name;                // "Bob"

// Bracket notation — key can be a variable or expression
user["age"];               // 30
const key = "name";
user[key];                 // "Bob" — dynamic key lookup

// Bracket notation is REQUIRED for keys that aren't valid identifiers
user["favorite color"];    // "blue" — user.favorite color would be a syntax error

Shorthand Property Names

const name = "Charlie";
const age = 28;

// ✅ Shorthand — when the variable name matches the key you want
const user2 = { name, age };
console.log(user2); // { name: "Charlie", age: 28 }

// Equivalent to the verbose form:
const user3 = { name: name, age: age };

BEGINNER3. Adding, Updating & Deleting Properties

const user = { name: "Alice" };

// Add a new property
user.role = "admin";
console.log(user); // { name: "Alice", role: "admin" }

// Update an existing property
user.role = "editor";
console.log(user.role); // "editor"

// Delete a property
delete user.role;
console.log(user); // { name: "Alice" }

// Checking if a property exists
console.log("name" in user);          // true
console.log(user.hasOwnProperty("name")); // true
console.log(user.age === undefined);  // true — missing property access returns undefined, no error

INTERMEDIATE4. Methods and this

A function stored as an object property is called a method. Inside a regular method, this refers to the object the method was called on.

const counter = {
    count: 0,
    increment() {          // shorthand method syntax (preferred)
        this.count++;
        return this.count;
    },
    decrement: function() { // equivalent long form
        this.count--;
        return this.count;
    }
};

console.log(counter.increment()); // 1
console.log(counter.increment()); // 2
console.log(counter.decrement()); // 1
⚠️ Arrow Functions as Methods: Arrow functions do NOT have their own this — they inherit it from the surrounding scope at the time they were defined. Using one as an object method almost always gives you the wrong this. 
const obj = {
    value: 10,
    getValue: () => this.value // ❌ 'this' here is NOT obj
};
console.log(obj.getValue()); // undefined

INTERMEDIATE5. Object Destructuring

Destructuring unpacks object properties into individual variables in one line.

const user = { name: "Dana", age: 40, city: "Austin" };

const { name, age } = user;
console.log(name, age); // "Dana" 40

// Renaming while destructuring
const { name: userName } = user;
console.log(userName); // "Dana"

// Default values (used only if the property is undefined/missing)
const { country = "USA" } = user;
console.log(country); // "USA" — user has no 'country' property

// Nested destructuring
const response = { data: { id: 1, meta: { verified: true } } };
const { data: { id, meta: { verified } } } = response;
console.log(id, verified); // 1  true

Destructuring in Function Parameters

function printUser({ name, age }) {
    console.log(`${name} is ${age}`);
}
printUser({ name: "Eve", age: 22 }); // "Eve is 22"

INTERMEDIATE6. Spread, Merging & Shallow Copy

const defaults = { theme: "light", lang: "en" };
const overrides = { theme: "dark" };

// Merge — later properties win on conflicts
const config = { ...defaults, ...overrides };
console.log(config); // { theme: "dark", lang: "en" }

// Shallow copy
const copy = { ...defaults };
copy.theme = "changed";
console.log(defaults.theme); // "light" — original untouched at the top level
⚠️ Shallow Copy Only: Spread only copies TOP-LEVEL properties. If a property's value is itself an object, both the original and the copy point to the SAME nested object. 
const original = { user: { name: "Frank" } };
const shallow = { ...original };
shallow.user.name = "George";
console.log(original.user.name); // "George" — the nested object is shared!

// For a real deep copy of JSON-safe data:
const deep = JSON.parse(JSON.stringify(original));
// or, in modern environments:
const deep2 = structuredClone(original);

BEGINNER7. Object.keys, values, entries

These static methods let you iterate over an object's properties in ways arrays' methods can be used on.

const scores = { alice: 90, bob: 75, carol: 88 };

Object.keys(scores);    // ["alice", "bob", "carol"]
Object.values(scores);  // [90, 75, 88]
Object.entries(scores); // [["alice",90], ["bob",75], ["carol",88]]

// Iterating with entries + destructuring
Object.entries(scores).forEach(([name, score]) => {
    console.log(name, score);
});
// "alice" 90   "bob" 75   "carol" 88

// Building a new object from entries (round trip)
const doubled = Object.fromEntries(
    Object.entries(scores).map(([name, score]) => [name, score * 2])
);
console.log(doubled); // { alice: 180, bob: 150, carol: 176 }

ADVANCED8. Optional Chaining & Nullish Coalescing

Optional chaining (?.) safely accesses deeply nested properties without throwing when an intermediate value is null/undefined. Pair it with nullish coalescing (??) for clean fallbacks.

const user = { address: null };

// Without optional chaining — throws!
// console.log(user.address.city); // ❌ TypeError: Cannot read properties of null

// With optional chaining — safe
console.log(user.address?.city); // undefined — no error

// Works on method calls too
user.notify?.(); // calls notify() only if it exists, otherwise does nothing

// Works on array access
const users = null;
console.log(users?.[0]?.name); // undefined — safe even though users itself is null

// Combine with ?? for a real fallback value
const city = user.address?.city ?? "Unknown";
console.log(city); // "Unknown"

ADVANCED9. Common Pitfalls

1. Objects Are Always Compared by Reference

console.log({ a: 1 } === { a: 1 }); // false — different objects, same shape
const obj = { a: 1 };
console.log(obj === obj); // true — same reference

2. Mutating a Shared Reference

function addAdminRole(user) {
    user.role = "admin"; // mutates the CALLER's object, since objects pass by reference
}
const person = { name: "Hana" };
addAdminRole(person);
console.log(person); // { name: "Hana", role: "admin" } — original was changed!

3. const Does Not Make an Object Immutable

const settings = { volume: 50 };
settings.volume = 100;   // ✅ allowed — const only locks the VARIABLE binding
console.log(settings.volume); // 100

// settings = {};        // ❌ TypeError — reassigning the binding IS blocked

// True immutability requires Object.freeze
const frozen = Object.freeze({ volume: 50 });
frozen.volume = 100;      // silently fails (or throws in strict mode)
console.log(frozen.volume); // 50 — unchanged

4. for...in Includes Inherited Properties

const base = { inherited: true };
const obj2 = Object.create(base);
obj2.own = true;

for (const key in obj2) {
    console.log(key); // "own" AND "inherited" — walks the prototype chain!
}

// Safer: only own properties
for (const key of Object.keys(obj2)) {
    console.log(key); // just "own"
}

INTERMEDIATE10. Best Practices

1. Use Shorthand Syntax

// ✅ Concise
const name = "Ivy", age = 33;
const user = { name, age, greet() { return "Hi " + this.name; } };

2. Prefer Destructuring Over Repeated Dot Access

// ✅ Cleaner
const { name, email, age } = user;

// ❌ Repetitive
const name2 = user.name;
const email2 = user.email;
const age2 = user.age;

3. Use Optional Chaining for Uncertain Nested Data

// ✅ Safe against missing API fields
const city = response?.data?.address?.city ?? "Unknown";

4. Avoid Deep Mutation — Create New Objects Instead

// ✅ Predictable, easier to track changes (especially in React-like state)
const updated = { ...config, timeout: 10000 };

// ❌ Mutating shared state directly
config.timeout = 10000;

5. Use Object.freeze for True Constants

const CONFIG = Object.freeze({
    API_URL: "https://api.example.com",
    MAX_RETRIES: 3
});
// Any attempt to modify CONFIG's properties is silently ignored (or throws in strict mode)

📋 Quick Reference Summary

Concept Key Points
Access Dot notation for known keys, bracket notation for dynamic/invalid-identifier keys.
Mutation Assign to add/update; delete obj.key to remove. Objects are mutable by default.
Methods Functions as properties. Use regular/shorthand methods for correct this.
Destructuring const { a, b } = obj unpacks properties, supports renaming and defaults.
Spread { ...obj, key: val } shallow-copies and merges — nested objects still shared.
Safe access obj?.a?.b for optional chaining, ?? fallback for nullish defaults.
