BEGINNER1. What is a Function?

A function is a reusable block of code that takes inputs (parameters), does some work, and optionally returns an output. Functions let you write logic once and run it as many times as needed.

Real-world analogy: A function is like an ATM machine. You insert your card and PIN (arguments), the machine processes your request (the function body), and hands you cash (the return value). You don't need to know the internal wiring.

Why Functions Matter

  • Reusability: Write the logic once, call it everywhere
  • Abstraction: Hide complex details behind a simple name
  • Testability: Isolated logic is easier to test
  • Composability: Small functions combine into bigger behavior
function add(a, b) {
    return a + b;
}

console.log(add(3, 4)); // 7

BEGINNER2. Function Declarations

A function declaration uses the function keyword with a name. Declarations are hoisted — fully available before their line in the code runs.

console.log(square(4)); // 16 — works even though called BEFORE the definition below!

function square(n) {
    return n * n;
}

Anatomy of a Function

function greet(name) {   // "greet" = name, "(name)" = parameter
    return "Hi " + name;  // function body + return value
}

const message = greet("Alice"); // "Alice" = argument passed in
console.log(message);           // "Hi Alice"
💡 Tip: A parameter is the name in the function's definition (name). An argument is the actual value you pass when calling it ("Alice"). People often use the words interchangeably, but technically they're different.

BEGINNER3. Function Expressions

A function expression stores an (often anonymous) function inside a variable. Unlike declarations, expressions are NOT hoisted — you can't call them before the line that defines them.

const cube = function(n) {
    return n ** 3;
};

console.log(cube(3)); // 27

// console.log(square2(3));  // ❌ ReferenceError — cannot access before initialization
const square2 = function(n) { return n * n; };

Named Function Expressions

You can optionally give a function expression an internal name — useful for recursion and clearer stack traces.

const factorial = function fact(n) {
    return n <= 1 ? 1 : n * fact(n - 1); // "fact" is only visible INSIDE the function
};
console.log(factorial(5)); // 120
// console.log(fact(5));   // ❌ ReferenceError — fact isn't visible outside

BEGINNER4. Arrow Functions

Arrow functions (=>) are a concise syntax introduced in ES6. They have no own this, no arguments object, and cannot be used as constructors.

// Full form
const add = (a, b) => {
    return a + b;
};

// Implicit return — single expression, no braces needed
const double = n => n * 2;

// No parameters need empty parens
const sayHi = () => console.log("Hi!");

// Returning an object literal needs parentheses (braces would be a function body)
const makePoint = (x, y) => ({ x, y });
console.log(makePoint(1, 2)); // { x: 1, y: 2 }
Regular function — own this: 
const obj = {
    value: 10,
    regular: function() {
        return this.value; // 'this' = obj
    }
};
console.log(obj.regular()); // 10
Arrow function — inherits this: 
const obj2 = {
    value: 10,
    arrow: () => {
        return this.value; // 'this' is NOT obj2
    }
};
console.log(obj2.arrow()); // undefined

INTERMEDIATE5. Default & Rest Parameters

Default Parameters

A default value is used only when the argument is undefined or omitted entirely — NOT for other falsy values like 0 or "".

function greet(name = "World") {
    return "Hi " + name;
}
console.log(greet());          // "Hi World"
console.log(greet("Alice"));   // "Hi Alice"
console.log(greet(undefined)); // "Hi World" — default kicks in
console.log(greet(""));        // "Hi "      — "" is NOT undefined, default does NOT kick in
console.log(greet(null));      // "Hi null"  — null is NOT undefined either!

Rest Parameters

...args collects any number of remaining arguments into a real array — replacing the old, array-like arguments object.

function sum(...nums) {
    return nums.reduce((acc, n) => acc + n, 0);
}
console.log(sum(1, 2, 3, 4)); // 10
console.log(sum());           // 0 — nums is just an empty array

// Rest must be the LAST parameter
function logFirst(first, ...rest) {
    console.log(first, rest);
}
logFirst(1, 2, 3, 4); // 1  [2, 3, 4]

INTERMEDIATE6. First-Class & Higher-Order Functions

In JavaScript, functions are first-class values — they can be stored in variables, passed as arguments, and returned from other functions, just like numbers or strings.

Functions as Values

const fn = Math.max;
console.log(fn(3, 7)); // 7 — a function reference stored in a variable

Higher-Order Functions

A higher-order function either takes a function as an argument, returns a function, or both.

// Takes a function as an argument (a callback)
[1, 2, 3].map(x => x * 2); // [2, 4, 6]

// Returns a function
function makeAdder(x) {
    return function(y) {
        return x + y;
    };
}
const add10 = makeAdder(10);
console.log(add10(5)); // 15

Callbacks

function fetchData(callback) {
    setTimeout(() => {
        callback("data loaded");
    }, 1000);
}
fetchData(result => console.log(result)); // "data loaded" (after 1s)

ADVANCED7. The this Keyword in Functions

The value of this depends on HOW a function is called, not where it's defined — except for arrow functions, which capture this from their surrounding (lexical) scope.

const obj = {
    name: "Alice",
    regularMethod: function() {
        console.log(this.name); // "Alice" — called as obj.regularMethod()
    },
    delayedArrow: function() {
        setTimeout(() => {
            console.log(this.name); // "Alice" — arrow inherits 'this' from delayedArrow
        }, 100);
    },
    delayedRegular: function() {
        setTimeout(function() {
            console.log(this.name); // undefined — regular function loses 'this' inside setTimeout
        }, 100);
    }
};
obj.regularMethod();
obj.delayedArrow();
obj.delayedRegular();
⚠️ Common Pitfall: Passing a regular method as a standalone callback (e.g. to setTimeout or an event listener) detaches it from its object — this is lost. Use an arrow function wrapper, or .bind(obj), to preserve it. 
class Counter {
    constructor() { this.count = 0; }
    increment() { this.count++; }
}
const c = new Counter();
const inc = c.increment;
// inc();          // ❌ TypeError-ish — 'this' is undefined/wrong here
const boundInc = c.increment.bind(c);
boundInc();        // ✅ works — 'this' is explicitly locked to c

ADVANCED8. IIFE (Immediately Invoked Function Expression)

An IIFE is a function that runs the instant it's defined — useful for creating an isolated scope that doesn't pollute the surrounding namespace.

(function() {
    console.log("runs immediately");
})();
// Output: "runs immediately"

// Arrow function IIFE
(() => {
    console.log("also runs immediately");
})();

// IIFE with a return value — classic private-state (module) pattern
const counterModule = (function() {
    let count = 0; // private — invisible from outside
    return {
        increment() { count++; return count; },
        get() { return count; }
    };
})();

console.log(counterModule.increment()); // 1
console.log(counterModule.increment()); // 2
// console.log(counterModule.count);    // undefined — count is private
💡 Tip: IIFEs were essential before ES6 modules existed — they were the main way to avoid leaking variables into the global scope. Today, ES modules (import/export) handle most of that need, but the pattern still appears in bundler output and one-off setup scripts.

ADVANCED9. Common Pitfalls

1. Forgetting return

function add(a, b) {
    a + b; // ⚠️ computes the value but never returns it
}
console.log(add(2, 3)); // undefined

2. Arrow Functions as Object Methods

const obj = {
    value: 42,
    getValue: () => this.value // ❌ arrow has no own 'this' — not obj
};
console.log(obj.getValue()); // undefined, not 42

// ✅ Use a regular function (or shorthand method syntax) instead
const obj2 = {
    value: 42,
    getValue() { return this.value; }
};
console.log(obj2.getValue()); // 42

3. Default Parameters Only Trigger on undefined

function setVolume(v = 50) {
    return v;
}
console.log(setVolume(0));    // 0 — NOT replaced by default, 0 !== undefined
console.log(setVolume());     // 50 — default applies here

4. Mutating Objects Passed as Arguments

function addRole(user) {
    user.role = "admin"; // mutates the ORIGINAL object — objects are passed by reference
}
const person = { name: "Bob" };
addRole(person);
console.log(person); // { name: "Bob", role: "admin" } — original changed!

INTERMEDIATE10. Best Practices

1. Prefer const for Function Expressions

// ✅ Prevents accidental reassignment
const calculateTotal = (items) => items.reduce((sum, i) => sum + i.price, 0);

2. Keep Functions Small and Single-Purpose

// ✅ Each function does ONE thing
function validateEmail(email) { /* ... */ }
function sendWelcomeEmail(email) { /* ... */ }

// ❌ One giant function doing everything is hard to test and reuse

3. Use Arrow Functions for Callbacks, Regular for Methods

// ✅ Arrow — no 'this' confusion in a callback
[1,2,3].map(n => n * 2);

// ✅ Regular/shorthand — correct 'this' binding for object methods
const obj = {
    data: [1,2,3],
    sum() { return this.data.reduce((a,b) => a+b, 0); }
};

4. Name Your Functions for Better Stack Traces

// ✅ Named — shows up clearly in error stack traces and debuggers
const processOrder = function processOrder(order) { /* ... */ };

// Anonymous — harder to spot in a stack trace
const processOrder2 = function(order) { /* ... */ };

5. Document Parameters for Non-Obvious Functions

/**
 * Calculates compound interest.
 * @param {number} principal - initial amount
 * @param {number} rate - annual interest rate (e.g. 0.05 for 5%)
 * @param {number} years - number of years
 */
function compoundInterest(principal, rate, years) {
    return principal * Math.pow(1 + rate, years);
}

📋 Quick Reference Summary

Concept Key Points
Declaration function name(){} — hoisted, callable before its definition line.
Expression const f = function(){} — not hoisted.
Arrow function const f = () => {} — concise, no own this/arguments.
Default params Apply only when the argument is undefined.
Rest params ...args collects remaining arguments into a real array.
Higher-order Takes and/or returns functions — the basis of callbacks and functional patterns.
IIFE (function(){})() — runs immediately, creates a private scope.
