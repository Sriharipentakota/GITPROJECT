BEGINNER1. How page.route() Works

page.route(pattern, handler) places a handler between the browser and the network. Every request whose URL matches the pattern is intercepted before it leaves the browser, and control passes to your handler function, which receives a Route object.

await page.route('**/api/users', route => {
  // your handler decides what happens to this request
});
await page.goto('/');
⚠️ Common Pitfall: Register routes before calling page.goto(). If you register a route after navigation, the very first request (and possibly more) will already have gone out unintercepted.

BEGINNER2. Mocking Responses with fulfill()

route.fulfill() returns a completely synthetic response — the real server is never contacted.

await page.route('**/api/todos', route => route.fulfill({
  status: 200,
  json: [],   // empty list — automatically JSON-serialized
}));

Testing an Empty State and an Error State

test('shows empty state when API returns no items', async ({ page }) => {
  await page.route('**/api/todos', route => route.fulfill({
    status: 200,
    json: [],
  }));

  await page.goto('/todos');
  await expect(page.getByTestId('empty-state')).toBeVisible();
});

test('shows error banner when API fails', async ({ page }) => {
  await page.route('**/api/todos', route => route.fulfill({
    status: 500,
    body: 'Internal Server Error',
  }));

  await page.goto('/todos');
  await expect(page.getByRole('alert')).toBeVisible();
});
Why mocking matters: reproducing a "server returned 500" or "server returned empty list" scenario against a real backend is often impossible or fragile. Mocking makes every edge case deterministic and instantly reproducible.

BEGINNER3. Blocking Requests with abort()

await page.route(/google-analytics\.com/, route => route.abort());
await page.route('**/*.{png,jpg,gif,svg}', route => route.abort());

Blocking analytics beacons, ad scripts, and images can significantly speed up test execution and remove sources of nondeterminism (e.g. third-party scripts that occasionally fail to load).

💡 Tip: route.abort() makes the browser see a genuine network error — good for testing your app's offline/error-handling UI, not just for cleaning up test noise.

INTERMEDIATE4. Passing Through with continue()

await page.route('**/api/**', route =>
  route.continue({
    headers: { ...route.request().headers(), 'x-test-id': 'suite-42' },
  })
);

route.continue() forwards the request essentially unchanged — optionally with modified headers, method, or post data. This is useful for tagging requests (so your backend logs can identify test traffic) without altering the actual response.

INTERMEDIATE5. Spy-and-Modify with route.fetch()

When you want the real response but need to tweak it before the page sees it, use route.fetch() to make the real request yourself, then route.fulfill() with a modified body.

await page.route('**/api/products', async route => {
  const res  = await route.fetch();
  const json = await res.json();
  json.push({ id: 999, name: 'Injected Item' });
  await route.fulfill({ json });
});

Injecting a Promoted Product

test('dashboard includes promoted product', async ({ page }) => {
  await page.route('**/api/products', async route => {
    const res  = await route.fetch();
    const json = await res.json();
    const modified = [{ id: 999, name: 'Promoted!', featured: true }, ...json];
    await route.fulfill({ json: modified });
  });

  await page.goto('/dashboard');
  await expect(page.locator('.product-card').first()).toContainText('Promoted!');
});

INTERMEDIATE6. URL Patterns: Glob, Exact, RegExp

Pattern type Example Matches
Glob string '**/api/users**' Any URL containing /api/users regardless of host or query string
Exact string 'https://api.example.com/health' Only that exact URL
RegExp /analytics|tracking/ Any URL matching the regular expression
⚠️ Common Pitfall: Multiple routes matching the same URL fire in LIFO order (last registered wins first). A broad catch-all route registered after a specific one can silently shadow it — register the most specific patterns last if they need to take precedence.

ADVANCED7. Passive Monitoring and context.route()

For read-only inspection without altering traffic, use event listeners instead of routes:

page.on('request', req => {
  console.log(req.method(), req.url());
});
page.on('response', res => {
  console.log(res.status(), res.url());
});

Collecting API Calls During a Flow

test('checkout fires the order-complete event', async ({ page }) => {
  await page.route(/analytics|tracking|hotjar/, route => route.abort());

  const apiCalls: string[] = [];
  page.on('request', req => {
    if (req.url().includes('/api/')) apiCalls.push(req.url());
  });

  await page.goto('/cart');
  await page.getByRole('button', { name: 'Place order' }).click();
  await expect(page).toHaveURL('/confirmation');

  expect(apiCalls.some(u => u.includes('/api/orders'))).toBe(true);
});

context.route() applies the same interception logic to every page in a browser context — including pages/tabs opened later — whereas page.route() only covers that one page.

ADVANCED8. Replaying HAR Files

await page.routeFromHAR('fixtures/api.har', { url: '**/api/**' });

page.routeFromHAR() replays a previously-recorded HTTP Archive (HAR) file — letting you mock an entire realistic API surface without hand-writing every response. Record one with npx playwright open --save-har=api.har <url> or via context.routeFromHAR(..., { update: true }) during a real session.

Remove any handler with page.unroute(pattern) when it's no longer needed within a test.

ADVANCED9. Common Pitfalls

⚠️ Pitfall 1 — Forgetting to resolve the route: Every handler must call exactly one of fulfill(), abort(), or continue(). Forgetting to call any of them leaves the request hanging until the test's timeout — a frustrating failure mode with no obvious error message.
⚠️ Pitfall 2 — Over-mocking until the test proves nothing real: Mocking every single endpoint can make a test pass even when the real integration is broken. Reserve heavy mocking for edge cases (errors, empty states) that are hard to reproduce naturally, and keep some tests exercising the real API end-to-end.

📋 Quick Reference Summary

Concept Key Points
page.route() Register before goto(); handler must call fulfill(), abort(), or continue().
fulfill() Mock a synthetic response — status, headers, json/body.
abort() Simulate a network error — good for blocking noise or testing offline UI.
route.fetch() Forward to the real server, then modify the response before fulfill().
Patterns Glob, exact string, or RegExp; multiple matches fire LIFO.
Passive listeners page.on('request'/'response') for read-only inspection.
routeFromHAR Replays a recorded HAR file to mock a whole API surface at once.
