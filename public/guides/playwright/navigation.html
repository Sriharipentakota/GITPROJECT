BEGINNER1. page.goto() Basics

page.goto(url, options) is the primary way to navigate. It accepts a full URL, or a relative path if baseURL is configured in playwright.config.ts.

await page.goto('https://example.com');
await page.goto('/login');                          // baseURL prepended
await page.goto('/slow', { timeout: 60_000 });      // per-call timeout override
💡 Tip: Setting use: { baseURL: 'http://localhost:3000' } once in the config means every test can use short relative paths, and switching environments (staging vs. production) is a one-line config change instead of a find-and-replace across every test file.

BEGINNER2. The waitUntil Option

By default, page.goto() waits for the load event — meaning all scripts, images, and stylesheets have finished loading. You can choose an earlier or later point with waitUntil:

Value Waits until When to use
'commit' First byte of the response received Earliest possible — rarely used directly in tests
'domcontentloaded' HTML parsed, before external resources finish Fast SPAs where you don't need images/fonts loaded
'load' (default) All resources (scripts, images, CSS) loaded General-purpose default — safe for most pages
'networkidle' No network activity for 500 ms Data-heavy pages that fetch content after initial load 
await page.goto('/static-page', { waitUntil: 'domcontentloaded' }); // fastest
await page.goto('/regular-page', { waitUntil: 'load' });             // default
await page.goto('/data-heavy-page', { waitUntil: 'networkidle' });   // thorough
⚠️ Common Pitfall: 'networkidle' is tempting for "wait until everything is really done," but pages with polling requests (analytics beacons, live chat widgets, websocket keep-alives) never go network-idle — the navigation will hang until timeout. Prefer waiting for a specific element or using a web-first assertion instead of leaning on networkidle as a catch-all.

BEGINNER3. Waiting After a Triggered Navigation

Not every navigation happens via page.goto() — clicking a link or submitting a form can trigger one too. In those cases, use waitForURL() or waitForLoadState() after the action.

await page.getByRole('link', { name: 'Products' }).click();
await page.waitForURL('/products');                // exact string
await page.waitForURL(/\/profile\/\d+/);           // regex pattern
await page.waitForURL('**/checkout**');            // glob pattern
await page.waitForLoadState('networkidle');

INTERMEDIATE4. Reading Current State: url() vs title()

This is a small but important distinction that trips up newcomers:

page.url() — synchronous: 
const url = page.url();
// Returns the string immediately —
// no Promise, no await needed
page.title() — asynchronous: 
const title = await page.title();
// Returns a Promise — must be awaited
// because it queries the DOM
💡 Tip: page.url() is fast because Playwright already tracks the current URL internally without a round trip. page.title() has to read the live <title> element from the page, which requires a call across the automation protocol — hence the Promise.

INTERMEDIATE5. Asserting Navigation with expect()

Always prefer the web-first assertions over manually comparing page.url() or page.title() — they auto-retry, which makes them resilient to redirects and in-flight navigation.

await expect(page).toHaveURL('/dashboard');
await expect(page).toHaveURL(/\/user\/\d+/);
await expect(page).toHaveTitle('My App — Home');
await expect(page).toHaveTitle(/Dashboard/);

Full Login-Redirect Example

test('login redirects to dashboard', async ({ page }) => {
  await page.goto('/login');

  await page.getByLabel('Email').fill('user@example.com');
  await page.getByLabel('Password').fill('secret');
  await page.getByRole('button', { name: 'Sign in' }).click();

  // Auto-retries until the redirect completes — no manual wait needed
  await expect(page).toHaveURL('/dashboard');
  await expect(page).toHaveTitle(/Dashboard/);
});
Why this beats expect(page.url()).toBe(...): if the redirect takes 200ms to complete, a raw equality check on page.url() called too early will see the old URL and fail — even though the app is working correctly. toHaveURL() keeps checking until it matches or times out.

INTERMEDIATE6. Browser History: back, forward, reload

await page.goto('/home');
await page.getByRole('link', { name: 'About' }).click();
await expect(page).toHaveURL('/about');

await page.goBack();
await expect(page).toHaveURL('/home');

await page.goForward();
await expect(page).toHaveURL('/about');

await page.reload();
await expect(page).toHaveURL('/about');
await page.reload({ waitUntil: 'networkidle' });

These methods mirror exactly what a real user does with the browser's back/forward buttons and refresh — useful for verifying that state (form input, scroll position, selected tab) survives or resets as expected.

ADVANCED7. Multi-Page and Popup Navigation

test('external link opens a new tab', async ({ context, page }) => {
  await page.goto('/docs');

  const [newPage] = await Promise.all([
    context.waitForEvent('page'),
    page.getByRole('link', { name: 'View on GitHub' }).click(),
  ]);

  await newPage.waitForLoadState();
  await expect(newPage).toHaveURL(/github\.com/);
});
⚠️ Common Pitfall: If you click the link first and then call context.waitForEvent('page'), the new page may have already opened before your listener attached, and the promise will hang. Always start the listener and the triggering click together inside Promise.all().

ADVANCED8. Common Pitfalls

⚠️ Pitfall 1 — Racing a client-side redirect: Single-page apps often navigate via JavaScript router (no full page load), so waitForLoadState('load') may resolve before the router-driven URL change happens. Prefer waitForURL() or a web-first expect(page).toHaveURL() which watches the URL directly.
⚠️ Pitfall 2 — Hardcoding full URLs everywhere: Without a configured baseURL, tests scattered with https://staging.myapp.com/... become a maintenance burden the moment the environment changes. Centralize the origin in config.
💡 Tip: If a navigation seems to hang indefinitely, check whether the page fires ongoing background requests (websockets, polling) that prevent 'networkidle' from ever being reached — switch to 'load' or 'domcontentloaded' instead.

📋 Quick Reference Summary

Concept Key Points
page.goto() Primary navigation method; accepts relative paths when baseURL is set.
waitUntil commit → domcontentloaded → load (default) → networkidle, in order of thoroughness.
waitForURL / waitForLoadState Use after link clicks or form submits that trigger navigation.
url() vs title() url() is synchronous; title() returns a Promise and must be awaited.
Assertions Prefer expect(page).toHaveURL()/toHaveTitle() — they auto-retry through redirects.
History goBack(), goForward(), reload() mirror real browser navigation controls.
