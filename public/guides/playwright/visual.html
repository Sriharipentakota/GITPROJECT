BEGINNER1. Three Tools, Three Purposes

Tool What it captures Best for
📸 Screenshot A single PNG at one point in time Ad-hoc debugging, visual regression baselines
🎬 Video Continuous WebM recording of the whole session Watching exactly what happened during a failure
🔍 Trace DOM snapshots, network waterfall, console logs, timeline — all in one zip Deep, step-by-step debugging of a specific failure
How they relate: a screenshot is a photograph, a video is CCTV footage, and a trace is a full forensics kit — you can inspect the DOM at any moment, replay network requests, and read console output, all synchronized to the same timeline.

BEGINNER2. Ad-Hoc Screenshots

await page.screenshot({ path: 'debug.png' });
await page.screenshot({ path: 'full.png', fullPage: true });
await page.screenshot({
  clip: { x: 0, y: 0, width: 800, height: 400 },
});
await locator.screenshot({ path: 'element.png' });

Capturing Specific Regions

test('capture specific regions', async ({ page }) => {
  await page.goto('/dashboard');

  await page.screenshot({ path: 'test-results/dashboard-full.png', fullPage: true });

  await page.screenshot({
    path: 'test-results/header.png',
    clip: { x: 0, y: 0, width: 1280, height: 80 },
  });

  const chart = page.getByTestId('revenue-chart');
  await chart.screenshot({ path: 'test-results/revenue-chart.png' });
});

INTERMEDIATE3. Visual Regression with toHaveScreenshot()

expect(page).toHaveScreenshot('name.png') creates a baseline image on the first run and compares against it pixel-by-pixel on every subsequent run.

test('homepage matches visual baseline', async ({ page }) => {
  await page.goto('/');
  await expect(page).toHaveScreenshot('homepage.png');
});

// First run:  creates __snapshots__/homepage-1.png as the baseline
// Next runs:  compares pixel-by-pixel and fails on meaningful differences
// Update:     npx playwright test --update-snapshots
⚠️ Common Pitfall: Baselines are captured per-browser and per-platform by default (Chromium on Linux renders subtly differently from Chromium on Windows). Generate and commit baselines from the same environment your CI runs in — usually a Linux Docker container — or you'll see spurious diffs.

INTERMEDIATE4. Masking Dynamic Content

await expect(page).toHaveScreenshot('homepage.png', {
  mask: [page.getByTestId('live-ticker'), page.locator('.timestamp')],
  maxDiffPixels: 50,
});
Option Purpose
mask: [locator, ...] Paints a solid box over elements that change every run (timestamps, ads)
maxDiffPixels Tolerate up to N different pixels before failing
threshold Per-pixel color distance (0–1) allowed before a pixel counts as "different"

INTERMEDIATE5. Video Recording

// playwright.config.ts
use: { video: 'on-first-retry' }

// Accessing the video from within a test
const video = page.video();
await video?.saveAs('recordings/my-test.webm');

The recommended setting, video: 'on-first-retry', only records when a test is retried after failing — keeping disk usage low while still capturing evidence of real failures.

ADVANCED6. Traces — the Most Powerful Artifact

A trace is a single .zip file containing DOM snapshots at every action, a full network request waterfall, console messages, and timestamped screenshots — everything needed to understand exactly what the browser saw at each step.

# View a trace
npx playwright show-trace trace.zip
# Or drag-and-drop the zip onto trace.playwright.dev
What makes traces different from video: in a trace, you can hover over any recorded action to see the exact DOM at that instant, inspect the network request that was in flight, and read console output — none of which is possible by just watching a video.

ADVANCED7. Manual Trace Control

await context.tracing.start({
  screenshots: true,   // capture screenshots at each action
  snapshots:   true,   // capture DOM snapshots for hover inspection
  sources:     true,   // embed test source code
});

await page.goto('/');
await page.getByRole('button').click();

await context.tracing.stop({ path: 'trace.zip' });

Recording a Specific Failing Scenario

test('checkout flow trace', async ({ page, context }) => {
  await context.tracing.start({ screenshots: true, snapshots: true, sources: true });

  await page.goto('/cart');
  await page.getByRole('button', { name: 'Checkout' }).click();
  await page.getByLabel('Card number').fill('4111111111111111');
  await page.getByRole('button', { name: 'Pay' }).click();

  await context.tracing.stop({ path: 'test-results/checkout-trace.zip' });
});

ADVANCED8. Configuring Capture Modes

Mode Behavior Applies to
'off' Never record trace, video, screenshot
'on' Always record trace, video, screenshot
'on-first-retry' Only record when a test is retried trace, video
'retain-on-failure' Always record, but delete the artifact if the test passes trace, video
'only-on-failure' Capture a screenshot only when the test fails screenshot 
use: {
  trace:      'on-first-retry',
  screenshot: 'only-on-failure',
  video:      'retain-on-failure',
},

ADVANCED9. Common Pitfalls

⚠️ Pitfall 1 — Setting trace/video to 'on' everywhere: Recording everything for every test in CI generates enormous artifact sizes and slows uploads. Reserve 'on' for local debugging sessions; use 'on-first-retry' or 'retain-on-failure' in CI.
⚠️ Pitfall 2 — Not masking dynamic content in visual tests: A visual regression test on a page with a live clock, ticker, or ad banner will fail on almost every run unless you explicitly mask those regions — leading teams to abandon visual testing as "too flaky" when the real fix is a two-line mask array.
