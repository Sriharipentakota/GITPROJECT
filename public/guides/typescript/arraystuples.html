BEGINNER1. Typing Arrays

Definition

Arrays in TypeScript are annotated using either T[] or the equivalent generic form Array<T>, where T is the type of every element.

let names: string[] = ["Alice", "Bob", "Carol"];
let scores: Array = [95, 88, 76];

names.push("Dave");     // ✅ OK
// names.push(42);      // ❌ Error: Argument of type 'number' is not
//                          assignable to parameter of type 'string'
Two equivalent syntaxes: number[] and Array<number> mean exactly the same thing. T[] is more common for simple types; Array<T> can read more clearly for complex generic types.

Empty Arrays Need Annotations

let results: number[] = [];   // ✅ explicit - safe to push numbers later
// let results = [];          // inferred as any[] without an annotation

results.push(10);
// results.push("ten");       // ❌ Error, thanks to the annotation

BEGINNER2. Array of Objects and Union Element Types

Array of Objects

interface Task {
    id: number;
    title: string;
    done: boolean;
}

const tasks: Task[] = [
    { id: 1, title: "Write guide", done: false },
    { id: 2, title: "Review PR", done: true }
];

tasks.forEach((task) => console.log(task.title));

Arrays with Union Element Types

let mixed: (string | number)[] = ["id", 42, "name", 7];

mixed.forEach((item) => {
    if (typeof item === "string") {
        console.log(item.toUpperCase());
    } else {
        console.log(item.toFixed(2));
    }
});

Multidimensional Arrays

const grid: number[][] = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
];

console.log(grid[1][2]);   // 6

INTERMEDIATE3. readonly Arrays

Mark an array as immutable when it should never be mutated after creation, catching accidental .push()/.sort() calls at compile time.

const weekdays: readonly string[] = ["Mon", "Tue", "Wed", "Thu", "Fri"];
// weekdays.push("Sat");   // ❌ Error: Property 'push' does not exist
//                            on type 'readonly string[]'

// Equivalent generic form
const numbers: ReadonlyArray = [1, 2, 3];

// Producing a new array is still fine
const withSaturday = [...weekdays, "Sat"];   // ✅ OK - new array

as const for Fully Immutable Literals

const directions = ["north", "south", "east", "west"] as const;
// type is readonly ["north", "south", "east", "west"]

// directions.push("up");   // ❌ Error - readonly
// directions[0] = "up";    // ❌ Error - readonly
💡 Tip: readonly only prevents mutating methods and index assignment — it doesn't create a deep freeze. Nested objects inside a readonly array can still be mutated unless they're also readonly.

INTERMEDIATE4. Introducing Tuples

A tuple is an array with a fixed length and a known type at each position — unlike a regular array where every element shares the same type.

let point: [number, number] = [10, 20];
let entry: [string, number] = ["age", 30];

console.log(point[0]);   // 10 (typed as number)
console.log(entry[0]);   // "age" (typed as string)
console.log(entry[1]);   // 30 (typed as number)

// let bad: [string, number] = [30, "age"];   // ❌ Error: order matters
// point.push(30, 40);                         // technically allowed but discouraged

Real-World Example: useState-Style Tuples

function useToggle(initial: boolean): [boolean, () => void] {
    let state = initial;
    const toggle = () => { state = !state; };
    return [state, toggle];
}

const [isOpen, toggleOpen] = useToggle(false);
Real-world use case: React's useState hook returns a tuple [value, setter] so that destructuring assigns precise types to each position — something a same-typed array couldn't express.

INTERMEDIATE5. Optional and Rest Elements in Tuples

Optional Tuple Elements

let cssSize: [number, string?];

cssSize = [10];          // ✅ OK - second element optional
cssSize = [10, "px"];    // ✅ OK

Rest Elements in Tuples

type StringNumberBooleans = [string, number, ...boolean[]];

const record1: StringNumberBooleans = ["hi", 1];
const record2: StringNumberBooleans = ["hi", 1, true];
const record3: StringNumberBooleans = ["hi", 1, true, false, true];

Combining Fixed and Variadic Segments

type LogEntry = [level: "info" | "warn" | "error", message: string, ...details: unknown[]];

const entry: LogEntry = ["error", "Failed to save", { code: 500 }, "retrying"];

INTERMEDIATE6. Named Tuple Members

Labels can be added to tuple positions purely for readability and better editor tooltips — they don't change runtime behavior.

type RGB = [red: number, green: number, blue: number];

function toHex([red, green, blue]: RGB): string {
    return "#" + [red, green, blue]
        .map((c) => c.toString(16).padStart(2, "0"))
        .join("");
}

toHex([255, 0, 128]);   // "#ff0080"
💡 Tip: Named tuple elements show up in editor hover hints as red: number instead of just number, making tuple-heavy APIs much easier to use correctly.

INTERMEDIATE7. Numeric Enums

An enum defines a set of named constants. Numeric enums auto-increment starting from 0 unless you specify values.

enum Direction {
    Up,      // 0
    Down,    // 1
    Left,    // 2
    Right    // 3
}

let move: Direction = Direction.Up;
console.log(move);              // 0
console.log(Direction[0]);      // "Up" - reverse mapping

Custom Starting Values

enum HttpStatus {
    OK = 200,
    Created = 201,
    NotFound = 404,
    ServerError = 500
}

function handleResponse(status: HttpStatus) {
    if (status === HttpStatus.OK) {
        console.log("Success!");
    }
}

handleResponse(HttpStatus.OK);   // Success!

ADVANCED8. String Enums and const enum

String Enums

String enums require every member to have its own explicit value and don't support reverse mapping, but they're far more readable when logged or debugged.

enum Direction {
    Up = "UP",
    Down = "DOWN",
    Left = "LEFT",
    Right = "RIGHT"
}

console.log(Direction.Up);        // "UP" (not 0)
// console.log(Direction["UP"]);  // ❌ no reverse mapping for string enums

const enum — Zero Runtime Cost

const enum LogLevel {
    Info,
    Warn,
    Error
}

let level = LogLevel.Warn;
// Compiles down to: let level = 1;
// No LogLevel object is generated in the output JS at all
⚠️ Common Pitfall: const enum is inlined at compile time, which means it cannot be used across certain module boundaries (e.g. with isolatedModules, common in Babel/ts-jest/esbuild setups). Check your build tooling before relying on it.

ADVANCED9. Enums vs Union Literal Types

Modern TypeScript style often favors string literal unions over enums, since they require no runtime code and integrate more naturally with plain JavaScript objects.

enum: 
enum Status {
    Pending = "PENDING",
    Active = "ACTIVE",
    Closed = "CLOSED"
}

function setStatus(s: Status) {}
setStatus(Status.Active);
// Generates a real JS object at runtime
Union literal: 
type Status = "PENDING" | "ACTIVE" | "CLOSED";

function setStatus(s: Status) {}
setStatus("ACTIVE");
// Zero runtime footprint
Aspect enum Union literal type
Runtime code generated ✅ Yes (unless const enum) ❌ No
Works with plain string values ❌ No (needs the enum member) ✅ Yes
Namespacing (Status.Active) ✅ Yes ❌ No
Common in modern codebases Less common ✅ Increasingly preferred

ADVANCED10. Best Practices

1. Annotate Empty Arrays

// ✅ Good
const ids: number[] = [];

2. Use Tuples for Fixed, Heterogeneous Structures

// ✅ Good - clear meaning at each position
function divide(a: number, b: number): [quotient: number, remainder: number] {
    return [Math.floor(a / b), a % b];
}

3. Prefer Union Literals Over Enums for Simple Sets

// ✅ Often preferred in modern code
type Theme = "light" | "dark" | "system";

4. Reach for enum When You Need Namespacing or Reverse Lookup

// ✅ Good use case - grouped, related constants
enum Permission {
    Read = "READ",
    Write = "WRITE",
    Admin = "ADMIN"
}

5. Freeze Arrays That Represent Fixed Configuration

// ✅ Good
const SUPPORTED_LOCALES = ["en", "fr", "es"] as const;
type Locale = typeof SUPPORTED_LOCALES[number];   // "en" | "fr" | "es"

📋 Quick Reference Summary

Concept Key Points
T[] / Array<T> Homogeneous, variable-length collections
readonly T[] Blocks mutating methods; use as const for literal-frozen arrays
Tuples [T, U] Fixed-length, position-typed arrays; support optional/rest/named elements
Numeric enum Auto-incrementing named constants; supports reverse mapping
String enum Explicit string values per member; readable at runtime, no reverse mapping
const enum Inlined at compile time, zero runtime object generated
Union literal type Lightweight, no-runtime-cost alternative to simple enums
