BEGINNER1. Typing Promises

Definition

A Promise<T> represents a value of type T that will be available in the future, once the asynchronous operation completes.

const numberPromise: Promise = new Promise((resolve) => {
    setTimeout(() => resolve(42), 1000);
});

numberPromise.then((value) => {
    console.log(value.toFixed(2));   // ✅ 'value' is typed as number
});

Promise<void> for Side-Effect-Only Operations

function delay(ms: number): Promise {
    return new Promise((resolve) => setTimeout(resolve, ms));
}

delay(500).then(() => console.log("500ms passed"));

BEGINNER2. async Functions and Their Return Types

An async function always returns a Promise, even if you write a plain return statement inside it — TypeScript wraps the declared return type in Promise<...> automatically.

async function getUser(id: number): Promise<{ id: number; name: string }> {
    // pretend this is a network call
    return { id, name: "Amir" };
}

// You call it and 'await' the resolved value
async function main() {
    const user = await getUser(1);
    console.log(user.name);   // "Amir" - typed as string
}

Inferred Async Return Types

// TypeScript infers Promise without an explicit annotation
async function greet(name: string) {
    return `Hello, ${name}`;
}

BEGINNER3. await and Type Narrowing

async function fetchScore(): Promise {
    // simulate a lookup that might fail
    return Math.random() > 0.5 ? 95 : null;
}

async function displayScore() {
    const score = await fetchScore();
    if (score !== null) {
        console.log(score.toFixed(1));   // ✅ narrowed to number
    } else {
        console.log("No score available");
    }
}
💡 Tip: await "unwraps" a Promise<T> down to T. All the narrowing techniques from the Type Narrowing guide apply normally to the awaited value.

INTERMEDIATE4. Typing fetch and JSON Responses

The built-in fetch function returns Promise<Response>, and response.json() returns Promise<any> — so you should assert or validate the shape you expect.

interface Post {
    id: number;
    title: string;
    body: string;
}

async function getPost(id: number): Promise {
    const response = await fetch(`/api/posts/${id}`);
    if (!response.ok) {
        throw new Error(`Request failed: ${response.status}`);
    }
    const data = await response.json() as Post;   // assertion - json() is 'any'
    return data;
}

A Generic fetchJson Helper

async function fetchJson(url: string): Promise {
    const response = await fetch(url);
    if (!response.ok) {
        throw new Error(`Request failed: ${response.status}`);
    }
    return response.json() as Promise;
}

const post = await fetchJson("/api/posts/1");
console.log(post.title);   // ✅ typed as string
⚠️ Common Pitfall: Casting the result of response.json() is a compile-time-only promise — it doesn't validate the actual payload. For untrusted APIs, pair this with a runtime validation library (like Zod) to catch shape mismatches.

INTERMEDIATE5. Error Handling in Async Code

async function loadConfig(): Promise<{ apiUrl: string }> {
    try {
        const response = await fetch("/config.json");
        return await response.json();
    } catch (error) {
        // 'error' is typed as 'unknown' under strict settings - narrow it
        if (error instanceof Error) {
            console.error("Failed to load config:", error.message);
        }
        throw error;
    }
}

Rejected Promises and unknown

Promise.reject(new Error("Something broke")).catch((error: unknown) => {
    if (error instanceof Error) {
        console.log(error.message);
    }
});
💡 Tip: Under strict mode (specifically useUnknownInCatchVariables, on by default since TS 4.4), catch clause variables are typed as unknown rather than any, forcing you to narrow before accessing properties — see the Error Handling guide for the full pattern.

INTERMEDIATE6. Promise.all, allSettled, and race with Types

Promise.all — Tuple-Preserving

async function loadDashboard() {
    const [user, posts, notifications] = await Promise.all([
        fetchJson<{ id: number; name: string }>("/api/user"),
        fetchJson<{ id: number; title: string }[]>("/api/posts"),
        fetchJson("/api/notifications/count")
    ]);
    // user, posts, notifications each keep their own distinct type
    console.log(user.name, posts.length, notifications);
}

async function fetchJson(url: string): Promise {
    return fetch(url).then((r) => r.json());
}

Promise.allSettled — Per-Item Status

const results = await Promise.allSettled([
    fetchJson("/api/a"),
    fetchJson("/api/b")
]);

for (const result of results) {
    if (result.status === "fulfilled") {
        console.log(result.value);   // ✅ narrowed - value exists
    } else {
        console.log(result.reason);  // ✅ narrowed - reason exists
    }
}

ADVANCED7. The Awaited<T> Utility Type

Awaited<T> recursively unwraps nested Promises, mirroring what await does at runtime — including promises that resolve to other promises.

type A = Awaited>;                 // string
type B = Awaited>>;         // number (unwraps recursively)
type C = Awaited;                            // string (non-promise passthrough)

async function getData(): Promise> {
    return Promise.resolve({ id: 1 });
}

type DataType = Awaited>;
// { id: number }
Real-world use case: Awaited<ReturnType<typeof someAsyncFn>> is a very common pattern for deriving the resolved data type of an async function you don't own, without duplicating an interface by hand.

ADVANCED8. Async Generators and for await...of

async function* fetchPages(baseUrl: string): AsyncGenerator {
    let page = 1;
    while (page <= 3) {
        const response = await fetch(`${baseUrl}?page=${page}`);
        const items: string[] = await response.json();
        yield items;
        page++;
    }
}

async function processAllPages() {
    for await (const page of fetchPages("/api/items")) {
        console.log("Got page with", page.length, "items");
    }
}
💡 Tip: AsyncGenerator<T, TReturn, TNext> mirrors the regular Generator<T, TReturn, TNext> type, but every value produced by yield is wrapped as if it went through a Promise.

ADVANCED9. Typing Callback-to-Promise Conversions

Older Node.js-style APIs use error-first callbacks rather than Promises. Wrapping them requires carefully typing both the success and error paths.

import { readFile } from "fs";

function readFileAsync(path: string): Promise {
    return new Promise((resolve, reject) => {
        readFile(path, "utf-8", (error, data) => {
            if (error) {
                reject(error);
            } else {
                resolve(data);
            }
        });
    });
}

async function main() {
    const content = await readFileAsync("./data.txt");
    console.log(content.length);   // ✅ typed as string
}
💡 Tip: Node's built-in util.promisify does this conversion automatically and infers types correctly for most standard callback-style functions, so prefer it over hand-rolled wrappers when available.

ADVANCED10. Best Practices

1. Always Annotate the Resolved Type of Public Async Functions

// ✅ Good - clear contract for callers
export async function getUser(id: number): Promise { /* ... */ }
interface User { id: number; }

2. Validate External Data Instead of Blindly Asserting

// ✅ Better - runtime + compile-time safety together
import { z } from "zod";
const UserSchema = z.object({ id: z.number(), name: z.string() });
async function getUser(id: number) {
    const data = await fetch(`/api/users/${id}`).then((r) => r.json());
    return UserSchema.parse(data);   // throws if shape doesn't match
}

3. Narrow catch Variables Before Using Them

// ✅ Good
catch (error) {
    if (error instanceof Error) { console.error(error.message); }
}

4. Prefer Promise.all for Independent Concurrent Work

// ✅ Good - runs concurrently, preserves each result's type
const [a, b] = await Promise.all([taskA(), taskB()]);
declare function taskA(): Promise;
declare function taskB(): Promise;

5. Use Awaited<T> Instead of Manually Unwrapping Promise Types

// ✅ Good
type UserResult = Awaited>;
declare function getUser(): Promise<{ id: number }>;
