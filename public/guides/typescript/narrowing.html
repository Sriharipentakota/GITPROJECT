BEGINNER1. What is Type Narrowing?

Definition

Narrowing is TypeScript's process of refining a broad type (like a union) into a more specific one based on runtime checks in your code, such as if statements or typeof checks.

Real-world analogy: Narrowing is like a border checkpoint that first checks "is this a passport or a driver's license?" — once it knows which one, it can safely check fields specific to that document type. 
function printLength(value: string | string[]) {
    if (typeof value === "string") {
        console.log(value.length);   // ✅ narrowed to string
    } else {
        console.log(value.length);   // ✅ narrowed to string[]
    }
}
💡 Tip: Narrowing only happens within the block where the check is true. Once you leave that block, TypeScript reverts to the wider type.

BEGINNER2. Narrowing with typeof

function formatValue(value: string | number | boolean): string {
    if (typeof value === "string") {
        return value.trim();
    } else if (typeof value === "number") {
        return value.toFixed(2);
    } else {
        return value ? "yes" : "no";
    }
}

formatValue("  hi  ");   // "hi"
formatValue(3.14159);    // "3.14"
formatValue(true);       // "yes"

typeof Works with switch Too

function describe(value: string | number | undefined): string {
    switch (typeof value) {
        case "string":
            return `String: ${value}`;
        case "number":
            return `Number: ${value}`;
        default:
            return "Nothing provided";
    }
}
⚠️ Common Pitfall: typeof null returns "object" in JavaScript, a historical quirk. Use an explicit value === null check to separate null from real objects.

BEGINNER3. Truthiness and Equality Narrowing

Truthiness Narrowing

function printName(name: string | null | undefined) {
    if (name) {
        console.log(name.toUpperCase());   // ✅ narrowed - name is string here
    } else {
        console.log("No name provided");
    }
}

Equality Narrowing

function compare(a: string | number, b: string | boolean) {
    if (a === b) {
        // Only 'string' is common to both unions, so both narrow to string
        console.log(a.toUpperCase(), b.toUpperCase());
    }
}

Narrowing null and undefined with != null

function greet(name: string | null | undefined) {
    if (name != null) {   // catches both null AND undefined
        console.log(`Hello, ${name}`);   // ✅ narrowed to string
    }
}
⚠️ Common Pitfall: Truthiness narrowing on strings/numbers also excludes valid values like "" or 0. Prefer explicit != null checks when you specifically want to exclude only null/undefined.

INTERMEDIATE4. Narrowing with instanceof

class ValidationError extends Error {
    field: string;
    constructor(field: string, message: string) {
        super(message);
        this.field = field;
    }
}

function handleError(error: Error) {
    if (error instanceof ValidationError) {
        console.log(`Invalid field: ${error.field}`);   // ✅ narrowed
    } else {
        console.log(`Generic error: ${error.message}`);
    }
}

instanceof with Built-in Types

function formatDate(value: Date | string): string {
    if (value instanceof Date) {
        return value.toISOString();
    }
    return new Date(value).toISOString();
}

INTERMEDIATE5. Narrowing with in

The in operator checks whether a property exists on an object, which TypeScript can use to distinguish between object shapes that don't share a discriminant tag.

interface Car {
    drive(): void;
}

interface Boat {
    sail(): void;
}

function operate(vehicle: Car | Boat) {
    if ("drive" in vehicle) {
        vehicle.drive();   // ✅ narrowed to Car
    } else {
        vehicle.sail();    // ✅ narrowed to Boat
    }
}

in with Optional Properties

interface Admin {
    role: "admin";
    permissions: string[];
}

interface Guest {
    role: "guest";
}

function describe(user: Admin | Guest) {
    if ("permissions" in user) {
        console.log(user.permissions.join(", "));   // ✅ narrowed to Admin
    } else {
        console.log("Guest user");
    }
}

INTERMEDIATE6. Discriminated Union Narrowing

When every member of a union shares a common literal property, checking that single property narrows the entire object at once — the most reliable and readable narrowing pattern.

type Shape =
    | { kind: "circle"; radius: number }
    | { kind: "rectangle"; width: number; height: number }
    | { kind: "triangle"; base: number; height: number };

function area(shape: Shape): number {
    switch (shape.kind) {
        case "circle":
            return Math.PI * shape.radius ** 2;
        case "rectangle":
            return shape.width * shape.height;
        case "triangle":
            return (shape.base * shape.height) / 2;
    }
}
💡 Tip: This pattern (also called a "tagged union") is the backbone of most robust TypeScript state-machine and API-response modeling — see the Union & Intersection Types guide for more depth.

ADVANCED7. Custom Type Guards (is)

When built-in narrowing techniques aren't enough, you can write your own type predicate function using the value is Type return annotation.

interface Fish {
    swim(): void;
}

interface Bird {
    fly(): void;
}

function isFish(pet: Fish | Bird): pet is Fish {
    return (pet as Fish).swim !== undefined;
}

function move(pet: Fish | Bird) {
    if (isFish(pet)) {
        pet.swim();   // ✅ narrowed to Fish
    } else {
        pet.fly();    // ✅ narrowed to Bird
    }
}

Type Guards for Arrays with .filter()

const values: (string | null)[] = ["a", null, "b", null, "c"];

function isString(value: string | null): value is string {
    return value !== null;
}

const strings: string[] = values.filter(isString);
// Without the type guard, .filter would return (string | null)[]

ADVANCED8. Assertion Functions

Assertion functions don't return a boolean — instead they throw if a condition fails, and TypeScript narrows the type for all code that runs after the call.

function assertIsString(value: unknown): asserts value is string {
    if (typeof value !== "string") {
        throw new Error("Expected a string");
    }
}

function process(input: unknown) {
    assertIsString(input);
    console.log(input.toUpperCase());   // ✅ narrowed to string after the assertion
}

Generic assert() Helper

function assert(condition: unknown, message: string): asserts condition {
    if (!condition) {
        throw new Error(message);
    }
}

function divide(a: number, b: number): number {
    assert(b !== 0, "Division by zero");
    return a / b;   // TypeScript trusts b is non-zero going forward
}
⚠️ Common Pitfall: Assertion functions are a compile-time promise, not a runtime guarantee beyond what you actually check. A poorly written assertion (e.g. always returning without checking) creates false type safety.

ADVANCED9. Control Flow Analysis Nuances

Narrowing Is Lost Across Function Boundaries

function isValid(value: unknown): boolean {
    return typeof value === "string";
}

function process(value: unknown) {
    if (isValid(value)) {
        // value.toUpperCase();   // ❌ Error - TypeScript doesn't know
        //                           isValid() narrows to string; it only
        //                           returns 'boolean', not a type predicate
    }
}

// Fix: use a real type predicate instead
function isString2(value: unknown): value is string {
    return typeof value === "string";
}

Narrowing and Closures

function example(value: string | undefined) {
    if (value) {
        setTimeout(() => {
            // console.log(value.toUpperCase());   // ❌ Error in some cases -
            //   TypeScript can't guarantee 'value' hasn't changed by the
            //   time this closure runs (relevant with 'let' captured variables)
        }, 100);
    }
}
💡 Tip: When narrowing needs to survive into a callback, copy the narrowed value into a new const first: const safeValue = value; then reference safeValue inside the closure.

ADVANCED10. Best Practices

1. Prefer Discriminated Unions Over in/instanceof Chains

// ✅ Good - one property, clean switch
type Action = { type: "add"; value: number } | { type: "reset" };

2. Write Type Predicates for Reusable Checks

// ✅ Good
function isNonNull(value: T | null | undefined): value is T {
    return value !== null && value !== undefined;
}

const clean = [1, null, 2, undefined, 3].filter(isNonNull);   // number[]

3. Use Assertion Functions for Preconditions

// ✅ Good - fails fast with a clear type guarantee afterward
assert(user !== null, "User must be loaded before this point");

4. Capture Narrowed Values Before Using Them in Callbacks

// ✅ Good
if (value) {
    const safeValue = value;
    setTimeout(() => console.log(safeValue.toUpperCase()), 100);
}

5. Always Add an Exhaustiveness Check to Narrowing switch Statements

// ✅ Good
default: {
    const _exhaustive: never = shape;
    throw new Error(`Unhandled shape: ${JSON.stringify(_exhaustive)}`);
}

Truthiness / != null Filters out null/undefined/falsy values before use
instanceof Narrows class instances, including custom Error subclasses
in Narrows based on property presence across differently-shaped objects

value is Type Custom, reusable type guard function returning a boolean
asserts value is Type Throws on failure; narrows all subsequent code in scope
