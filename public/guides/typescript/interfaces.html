BEGINNER1. Why Name a Shape?

Definition

An interface gives a name to a specific object shape so you can reuse it across your codebase instead of repeating an inline type every time.

Real-world analogy: An interface is like a blueprint for a form. Instead of describing "a box for name, a box for age, a box for email" every single time, you hand people the blueprint and say "fill this out."

The Problem Without Named Types

// Repeating the same shape everywhere is error-prone
function printUser(user: { id: number; name: string; email: string }) { /* ... */ }
function saveUser(user: { id: number; name: string; email: string }) { /* ... */ }
function updateUser(user: { id: number; name: string; email: string }) { /* ... */ }

The Fix: Name It Once

interface User {
    id: number;
    name: string;
    email: string;
}

function printUser(user: User) { /* ... */ }
function saveUser(user: User) { /* ... */ }
function updateUser(user: User) { /* ... */ }
💡 Tip: By convention, interface names use PascalCase and are usually nouns describing the entity they model: User, Product, ApiResponse.

BEGINNER2. Defining Interfaces

Basic Syntax

interface Point {
    x: number;
    y: number;
}

const origin: Point = { x: 0, y: 0 };
const shifted: Point = { x: 10, y: 5 };

// const invalid: Point = { x: 0 };   // ❌ Error: Property 'y' is missing

Nested Object Shapes

interface Address {
    street: string;
    city: string;
    zip: string;
}

interface Customer {
    name: string;
    address: Address;
}

const customer: Customer = {
    name: "Jordan",
    address: { street: "1 Main St", city: "Springfield", zip: "00000" }
};

Array and Method Members

interface Cart {
    items: string[];
    total: number;
    checkout(): void;
}

const cart: Cart = {
    items: ["book", "pen"],
    total: 24.5,
    checkout() {
        console.log("Checking out...");
    }
};

BEGINNER3. Type Aliases

A type alias (created with the type keyword) gives a name to any type — not just object shapes.

type ID = string | number;
type Point = { x: number; y: number };
type Direction = "up" | "down" | "left" | "right";
type Callback = (error: Error | null, data?: string) => void;

let userId: ID = 42;
userId = "abc-123";   // ✅ also valid, ID is a union

Aliasing Primitives and Unions

type Age = number;
type Username = string;
type Result = { success: true; value: T } | { success: false; error: string };

const outcome: Result = { success: true, value: 100 };
💡 Tip: Unlike interfaces, type aliases can represent unions, tuples, primitives, and mapped types — not just object shapes. This makes them more flexible in some scenarios.

INTERMEDIATE4. Interface vs Type Alias

Both can describe an object shape, and in most everyday cases they're interchangeable. But there are real differences worth knowing.

Feature interface type
Object shapes ✅ Yes ✅ Yes
Unions / Intersections ❌ No (unions specifically) ✅ Yes
Can be extended (extends) ✅ Yes ✅ Yes (via &)
Declaration merging ✅ Yes (same name adds members) ❌ No (duplicate name errors)
Primitives, tuples, functions ❌ No (functions only via call signature) ✅ Yes

Side-by-Side Example

interface: 
interface Animal {
    name: string;
}

interface Dog extends Animal {
    breed: string;
}
type: 
type Animal = {
    name: string;
};

type Dog = Animal & {
    breed: string;
};
Rule of thumb: Use interface for public object/class shapes that might be extended later. Use type for unions, tuples, function types, and anything that isn't a plain object shape.

INTERMEDIATE5. Optional and Readonly Members

Optional Properties (?)

interface Product {
    id: number;
    name: string;
    discount?: number;   // may or may not be present
}

const item1: Product = { id: 1, name: "Mouse" };
const item2: Product = { id: 2, name: "Keyboard", discount: 0.1 };

Readonly Properties

interface Config {
    readonly apiKey: string;
    readonly createdAt: Date;
}

const config: Config = { apiKey: "abc123", createdAt: new Date() };
// config.apiKey = "xyz789";   // ❌ Error: Cannot assign to 'apiKey' because it is read-only

Readonly Arrays

interface Snapshot {
    readonly tags: readonly string[];
}

const snap: Snapshot = { tags: ["a", "b"] };
// snap.tags.push("c");   // ❌ Error: Property 'push' does not exist on
//                           type 'readonly string[]'
⚠️ Common Pitfall: readonly is shallow. A readonly property holding an object still allows mutating that object's own properties unless it too is marked readonly.

INTERMEDIATE6. Extending Interfaces

Single Extension

interface Animal {
    name: string;
    age: number;
}

interface Dog extends Animal {
    breed: string;
    bark(): void;
}

const rex: Dog = {
    name: "Rex",
    age: 3,
    breed: "Labrador",
    bark() { console.log("Woof!"); }
};

Extending Multiple Interfaces

interface Timestamped {
    createdAt: Date;
}

interface Identifiable {
    id: number;
}

interface Post extends Timestamped, Identifiable {
    title: string;
    body: string;
}

const post: Post = {
    id: 1,
    title: "Hello World",
    body: "My first post",
    createdAt: new Date()
};

Overriding Members When Extending

interface Shape {
    color: string;
}

interface Circle extends Shape {
    // must remain compatible with the base type
    color: "red" | "blue";
    radius: number;
}

INTERMEDIATE7. Interfaces for Functions and Indexable Types

Function Type Interfaces

interface Comparator {
    (a: number, b: number): number;
}

const ascending: Comparator = (a, b) => a - b;
const descending: Comparator = (a, b) => b - a;

[3, 1, 2].sort(ascending);   // [1, 2, 3]

Index Signatures

Index signatures describe objects used like dictionaries, where property names aren't known ahead of time.

interface StringDictionary {
    [key: string]: string;
}

const translations: StringDictionary = {
    hello: "hola",
    goodbye: "adios"
};

translations.thanks = "gracias";   // ✅ OK
// translations.count = 5;         // ❌ Error: number not assignable to string

Combining Known Keys with an Index Signature

interface Scores {
    average: number;
    [studentName: string]: number;
}

const scores: Scores = { average: 88, alice: 92, bob: 84 };

ADVANCED8. Declaration Merging

Unlike type aliases, declaring an interface with the same name twice in the same scope merges the members into one interface rather than causing an error.

interface Window {
    title: string;
}

interface Window {
    ts: TypeScript;
}

// The effective interface is now:
// interface Window {
//     title: string;
//     ts: TypeScript;
// }

interface TypeScript { version: string; }
Real-world use case: Library authors use declaration merging to let consumers extend built-in types, such as adding custom properties to the global Window or augmenting an Express Request object with a user field. 
// Augmenting Express's Request type in your own project
declare namespace Express {
    interface Request {
        user?: { id: number; role: string };
    }
}
⚠️ Common Pitfall: Because type aliases cannot merge, declaring type Window = {...} twice is a hard compile error. Only interfaces support this behavior.

ADVANCED9. Implementing Interfaces with Classes

interface Serializable {
    serialize(): string;
}

interface Identifiable {
    id: number;
}

class User implements Serializable, Identifiable {
    constructor(public id: number, private name: string) {}

    serialize(): string {
        return JSON.stringify({ id: this.id, name: this.name });
    }
}

const u = new User(1, "Kai");
console.log(u.serialize());   // {"id":1,"name":"Kai"}
💡 Tip: implements only checks the public shape of the class against the interface — it does not copy any behavior. You still have to write every method yourself. This is different from extends, which inherits implementation.

ADVANCED10. Best Practices

1. Prefer interface for Object Shapes, type for Everything Else

// ✅ Good
interface User { id: number; name: string; }
type Status = "active" | "inactive";

2. Keep Interfaces Small and Composable

// ✅ Good - compose small pieces
interface Identifiable { id: number; }
interface Timestamped { createdAt: Date; }
interface Post extends Identifiable, Timestamped { title: string; }

3. Mark Immutable Data as readonly

interface Config {
    readonly apiUrl: string;
}

4. Avoid Excessive Optional Properties

// ❌ Too permissive - hard to know what's actually required
interface Order { id?: number; total?: number; items?: string[]; }

// ✅ Better - be explicit about what's required
interface Order { id: number; total: number; items: string[]; }

5. Use Declaration Merging Sparingly

Reach for it only when augmenting third-party or global types — not as a general design pattern in your own code.

📋 Quick Reference Summary

Concept Key Points
interface Named object shape; supports extends and declaration merging
type Names any type: unions, tuples, functions, primitives, object shapes
Optional (?) Property may be omitted
readonly Prevents reassignment after initial creation (shallow)
extends Combine multiple interfaces into one richer shape
Index signatures Model dictionary-like objects with dynamic keys
implements Class promises to satisfy an interface's public shape
