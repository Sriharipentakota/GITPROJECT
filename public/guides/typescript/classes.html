BEGINNER1. Classes in TypeScript

Definition

TypeScript classes build on JavaScript's class syntax by adding type annotations for fields, constructor parameters, and methods, plus access modifiers that JavaScript lacks natively.

class Person {
    name: string;
    age: number;

    constructor(name: string, age: number) {
        this.name = name;
        this.age = age;
    }

    greet(): string {
        return `Hi, I'm ${this.name} and I'm ${this.age}.`;
    }
}

const p = new Person("Ivy", 28);
console.log(p.greet());   // Hi, I'm Ivy and I'm 28.
💡 Tip: Every field used in the constructor must be declared with a type at the class level first — TypeScript won't infer fields purely from assignments inside methods.

BEGINNER2. Typed Fields and Constructors

Fields with Default Values

class Counter {
    count: number = 0;         // default value, type inferred as number

    increment(): void {
        this.count++;
    }
}

const c = new Counter();
c.increment();
console.log(c.count);   // 1

Optional Fields

class Profile {
    username: string;
    bio?: string;   // may be undefined

    constructor(username: string) {
        this.username = username;
    }
}

const profile = new Profile("nova");
console.log(profile.bio);   // undefined

Definite Assignment Assertion (!)

class Service {
    // Assigned in an init() method, not the constructor
    apiClient!: ApiClient;

    init() {
        this.apiClient = new ApiClient();
    }
}

class ApiClient {}
⚠️ Common Pitfall: The ! definite assignment assertion silences the compiler but doesn't guarantee the field is actually set before use. Use it sparingly and only when you're certain of the initialization order.

INTERMEDIATE3. public, private, and protected

Access modifiers control which code can read or write a class member. This is a compile-time-only feature — the emitted JavaScript has no true enforcement (unless you use #private fields, covered in section 9).

Modifier Accessible From Default?
public Anywhere ✅ Yes - implicit if omitted
private Only within the declaring class ❌ No
protected The declaring class and its subclasses ❌ No 
class BankAccount {
    public accountHolder: string;
    private balance: number;
    protected accountNumber: string;

    constructor(holder: string, initial: number, accountNumber: string) {
        this.accountHolder = holder;
        this.balance = initial;
        this.accountNumber = accountNumber;
    }

    deposit(amount: number): void {
        this.balance += amount;   // ✅ OK - private accessible inside the class
    }

    getBalance(): number {
        return this.balance;
    }
}

const account = new BankAccount("Sam", 1000, "ACC-001");
// account.balance;      // ❌ Error: 'balance' is private
account.deposit(500);
console.log(account.getBalance());   // 1500

protected in Subclasses

class SavingsAccount extends BankAccount {
    showAccountNumber(): string {
        return this.accountNumber;   // ✅ OK - protected accessible in subclass
    }
}

// const sa = new SavingsAccount("Sam", 1000, "ACC-001");
// sa.accountNumber;   // ❌ Error: 'accountNumber' is protected

INTERMEDIATE4. Parameter Properties (Constructor Shorthand)

TypeScript lets you declare and initialize a field in one step by adding an access modifier directly to a constructor parameter.

// Without parameter properties (verbose)
class UserVerbose {
    public id: number;
    private name: string;

    constructor(id: number, name: string) {
        this.id = id;
        this.name = name;
    }
}

// With parameter properties (concise, same result)
class User {
    constructor(
        public id: number,
        private name: string,
        protected role: string = "member"
    ) {}

    getName(): string {
        return this.name;
    }
}

const user = new User(1, "Robin");
console.log(user.id);          // ✅ OK - public
console.log(user.getName());   // Robin
When to use it: Parameter properties are extremely common in real-world TypeScript for dependency injection style constructors, e.g. constructor(private http: HttpClient, private logger: Logger) {}.

INTERMEDIATE5. readonly Class Members

class Point {
    readonly x: number;
    readonly y: number;

    constructor(x: number, y: number) {
        this.x = x;
        this.y = y;
    }
}

const origin = new Point(0, 0);
// origin.x = 10;   // ❌ Error: Cannot assign to 'x' because it is read-only

Combining readonly with Parameter Properties

class Config {
    constructor(
        public readonly apiUrl: string,
        public readonly timeoutMs: number = 5000
    ) {}
}

const config = new Config("https://api.example.com");
// config.apiUrl = "https://other.com";   // ❌ Error

INTERMEDIATE6. Inheritance with extends

class Animal {
    constructor(protected name: string) {}

    move(distance: number = 0): void {
        console.log(`${this.name} moved ${distance}m.`);
    }
}

class Dog extends Animal {
    bark(): void {
        console.log(`${this.name} says Woof!`);
    }

    // Overriding a method - must remain compatible with the base signature
    move(distance: number = 5): void {
        console.log("Running...");
        super.move(distance);   // call the base class implementation
    }
}

const rex = new Dog("Rex");
rex.bark();     // Rex says Woof!
rex.move();     // Running... / Rex moved 5m.
⚠️ Common Pitfall: If a subclass constructor is defined, it must call super(...) before accessing this, or TypeScript raises a compile error.

ADVANCED7. Abstract Classes

An abstract class cannot be instantiated directly — it exists to be extended, and can declare methods that subclasses must implement.

abstract class Shape {
    abstract area(): number;         // no body - must be implemented by subclasses

    describe(): string {              // regular method - inherited as-is
        return `This shape has an area of ${this.area()}`;
    }
}

class Circle extends Shape {
    constructor(private radius: number) {
        super();
    }

    area(): number {
        return Math.PI * this.radius ** 2;
    }
}

// const shape = new Shape();   // ❌ Error: Cannot create an instance of an abstract class
const circle = new Circle(3);
console.log(circle.describe());   // This shape has an area of 28.27...
Real-world use case: Abstract classes are ideal for defining a shared template (e.g. a Repository base class with a common save() flow) while forcing each subclass to supply the specifics (e.g. validate()).

ADVANCED8. Interfaces with implements

interface Flyable {
    altitude: number;
    fly(): void;
}

interface Swimmable {
    depth: number;
    swim(): void;
}

// A class can implement multiple interfaces at once
class Duck implements Flyable, Swimmable {
    altitude = 0;
    depth = 0;

    fly(): void {
        this.altitude = 10;
        console.log("Duck is flying at", this.altitude);
    }

    swim(): void {
        this.depth = 2;
        console.log("Duck is swimming at depth", this.depth);
    }
}
💡 Tip: implements only checks the class's public shape against the interface at compile time — it copies no behavior. Compare this with extends, which shares actual implementation from a base class.

ADVANCED9. Static Members and True Private (#) Fields

Static Members

class IdGenerator {
    private static counter = 0;

    static next(): number {
        IdGenerator.counter += 1;
        return IdGenerator.counter;
    }
}

console.log(IdGenerator.next());   // 1
console.log(IdGenerator.next());   // 2

ECMAScript #private Fields

TypeScript's private keyword is compile-time only — it's erased in the compiled JavaScript, so the field is still technically accessible at runtime. Native # fields are enforced by the JavaScript engine itself, even after compilation.

class SecureVault {
    #secret: string;

    constructor(secret: string) {
        this.#secret = secret;
    }

    reveal(): string {
        return this.#secret;
    }
}

const vault = new SecureVault("classified");
console.log(vault.reveal());   // classified
// console.log(vault.#secret); // ❌ SyntaxError at compile time AND blocked at runtime
// console.log((vault as any).secret);  // undefined - can't reach it via any either
Feature private keyword #field
Enforced at compile time ✅ Yes ✅ Yes
Enforced at runtime ❌ No - erased to a normal property ✅ Yes - true JS-level privacy
Bypassable via as any ✅ Yes ❌ No

ADVANCED10. Best Practices

1. Prefer Parameter Properties for Simple Constructors

// ✅ Good
class OrderService {
    constructor(private repository: OrderRepository) {}
}
class OrderRepository {}

2. Default to private, Widen Only When Necessary

// ✅ Good - start restrictive, loosen deliberately
class Cache {
    private store = new Map();
}

3. Use Abstract Classes for Shared Templates

// ✅ Good
abstract class Validator {
    abstract isValid(value: T): boolean;
    assert(value: T): void {
        if (!this.isValid(value)) throw new Error("Invalid value");
    }
}

4. Reach for # Fields When True Runtime Privacy Matters

// ✅ Good for security-sensitive internal state
class TokenStore {
    #token: string = "";
}

5. Keep Inheritance Hierarchies Shallow

Prefer composition (accepting collaborators via constructor) over deep inheritance chains, which become hard to reason about and refactor.

📋 Quick Reference Summary

Concept Key Points
public / private / protected Compile-time access control; public is the implicit default
Parameter properties Declare + assign a field directly in the constructor signature
readonly Field can be set once (declaration or constructor), never reassigned after
extends Inherit implementation from a base class; use super() to reach it
abstract class Cannot be instantiated; may declare methods subclasses must implement
implements Class promises to satisfy an interface's shape; no behavior sharing
#field True runtime-private field enforced by the JS engine itself
